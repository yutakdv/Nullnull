- 웹: 외부에서 접속 가능한 최종 URL을 제출한다.

- 별도 계정이 필요하면 개인 계정이 아닌 테스트 전용 계정을 만든다.

  - 이메일 ID의 비밀번호 표기는 공식 자료 사이에 차이가 있으므로 아래 주의를 따른다.
- Nullnull 제출 결정: `로그인 불필요`를 선택하고 익명 session에서 저장을 포함한 핵심 흐름을 완결한다. 로그인 CTA는 P1 `준비 중`이며 요청을 보내지 않는다.

## 7. OpenAPI 활용 규칙

- 한국관광공사 OpenAPI를 실제 서비스에서 사용해야 심사 대상이 된다.
- 제출된 인증키를 통해 개발 기간의 API별 호출 이력을 확인할 수 있다.
- 파일 데이터만 활용한 것은 필수 OpenAPI 활용으로 인정되지 않는다.
- 데이터 동기화 문제를 줄이기 위해 실시간 호출 방식이 권고된다.
- 로컬 DB에 전체 데이터를 저장해 서비스하고 호출 이력이 남지 않으면 불이익이 생길 수 있다.
- 영속 저장이 불가피하면 별도 신청서와 제공기관 확인이 필요하므로 OpenAPI 문의처에 사전 질의한다.
- 기능설명서와 제출 시스템에는 최종 배포본에서 실제 호출한 API만 적는다.
- 키와 디코딩·인코딩 인증정보는 제출 시스템에만 입력하고 Git, 프론트 번들, 화면 캡처, 기능설명서 PDF에 노출하지 않는다.

### 생성형 AI와 AI 코딩 도구

- 공식 FAQ는 서비스 기능의 생성형 AI와 개발 과정의 AI 코딩 보조 도구 사용을 허용하며, 그 자체에 제한이나 감점을 두지 않는다고 안내한다.
- 평가의 핵심은 도구 사용량이 아니라 안정적으로 구동되는 완성 서비스다.
- Nullnull은 Claude Code를 개발 보조에 활용하되 사람의 상대 검토, 계약 검증과 테스트를 대체하지 않는다. secret·개인정보·provider 원문은 prompt나 공유 transcript에 넣지 않는다.

## 8. 데이터 출처 표시

공공데이터 출처의 텍스트 표기는 필수다. 기관이 서비스를 직접 운영하는 것처럼 오인시키는 명칭·로고 사용과는 구분된다.

- 허용 예시: `출처: ⓒ한국관광공사`
- 허용 예시: `출처: ⓒ한국관광콘텐츠랩`
- 지양: `TourAPI`만 단독으로 표시
- 공식 CI·BI 로고 이미지는 별도 허가 없이 사용하지 않고 텍스트로 출처를 표시한다.

## 9. 위치정보 관련 주의

- 개인 위치를 단말기 내부에서만 처리하고 서버로 보내지 않거나 개인을 식별할 수 없게 익명·가명 처리하는 경우에는 신고 대상이 아닐 수 있다.
- 서비스 제공을 위해 개인위치정보를 서버로 전송하면 DB 저장 여부와 관계없이 위치기반서비스사업 신고 대상이 될 수 있다.
- 실제 적용 여부는 데이터 흐름에 따라 달라지므로 [위치정보지원센터](https://www.lbsc.kr/)에 사전 검토를 요청한다.
- Nullnull 제출 결정: 위치 capability를 OFF로 하고 browser geolocation permission도 요청하지 않는다. 장소/지역 직접 선택과 다음 일정 기준으로 동작한다.

## 10. 심사 제외·운영 위험

- 타 부문에 동일 서비스를 중복 출품하지 않는다.
- 동일 서비스로 본 공모전 수상 또는 한국관광공사 지원사업 수혜 이력이 있으면 제외될 수 있다.
- 지정과제는 하나만 선택하며 최종 제출한 과제를 기준으로 심사한다.
- 선택 과제의 관광 문제를 해결하는 기능과 한국관광공사 OpenAPI 활용을 모두 완성해야 한다.
- 입력 항목·첨부파일 누락, 잘못된 부문 양식, 기능설명서 임의 변경은 심사 제외 사유가 될 수 있다.
- 테스트 계정으로 로그인할 수 없거나 서비스 URL이 열리지 않으면 기능 확인이 불가능하다.
- 웹과 앱이라는 형태 자체는 평가에 영향을 주지 않지만 앱은 스토어 승인 리스크가 추가된다.
