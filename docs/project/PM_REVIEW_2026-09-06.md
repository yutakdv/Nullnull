# 2026-09-06 Figma·Backend·AI PM 점검

**판정: 문서의 기본 구조와 안전 원칙은 갖췄지만, 전체 기능을 계약 확정 상태로 보고 개발하기에는 공백이 있다.** 생성 초안, 편집 저장, 가져오기, 시간, 후보 연결, 콘텐츠 출처, Live 입력/출력과 복구 흐름을 먼저 닫아야 한다. 이 검토는 구현 완료나 출시 승인이 아니다.

검토 기간은 2026-09-06~07이다. 문서 ID의 날짜는 검토 시작일이며 마지막 로컬 검증은 09-07에 마쳤다.

대상은 `~/Desktop/Nullnull`의 현재 `backend` 작업 트리다. 기존 미커밋 변경을 포함한 파일을 기준으로 검토했다. 과거 삭제한 PM 문서를 복원하지 않았고 기능 코드·Figma 원본·Git 이력·원격 서비스는 변경하지 않았다.

## 3. 발견 사항

24개 ID는 이번 검토의 추적 ID다. **차단**은 해당 기능의 계약 확정/출시 차단이며 전체 작업 중단이 아니다. **보완**은 정책·실패 상태·검증 추가가 필요하다는 뜻이다. 모두 Open이다. 오기 정정만으로 기능까지 해결됐다고 처리하지 않는다.

### PM-001 · P0 언어·게스트·피드 약속과 control 충돌

- **차단 / 기존 FCR-001~003/006 재확인.** English는 준비 중이고 feed/post의 following/latest/search/bell/follow/혼잡 정렬은 활성처럼 보인다. profile은 로그인해야 저장된다고 설명한다.
- 실제 계약은 KO/EN·익명 저장·고정 feed다. intro의 관심사 기반 탐색 소개와 공모전 문서의 “개인화 Feed”도 고정 순서와 구분해야 한다.
- **조치/검증:** KO/EN 전환·복구, guest 보존 안내, P1 요청 0건, P0 문구와 배포 기능 일치. 해당 Figma: `388:277`, `388:321`, `391:310`, `396:2926`, `398:611`, `422:2925`.
- **연결:** FR-ONB-02/03, FR-FED-01~05, FR-PRO-01/02; BA-011/032/073. FE 작성, BE/AI 계약 검토, PM 문구 검토.

### PM-002 · P0 프로필·편집의 보조 상태 미확인

- **차단 / FCR-016.** `422:2925`에는 여행/이력/관심사/데이터 안내가 있으나 언어 변경, 여행 삭제, 전체 데이터 삭제 확인·진행·부분 실패·완료·receipt 분실 흐름을 확인할 수 없다. 시간/duration/예약 편집의 독립 화면도 없다.
- [제품](../product/PRODUCT_SPEC.md)·[Privacy](../security/PRIVACY_REQUIREMENTS.md)에는 P0로 존재한다. 화면 52개라는 숫자가 이를 보장하지 않는다.
- **조치/검증:** 새 frame 또는 component variant에 각 진입점→확인→성공/실패→복귀를 연결한다. 기간 축소 실패·빈 여행·history empty/expired·KO/EN·keyboard·401/409/410도 포함한다.
- **연결:** FR-PRO-02~05, FR-SES-04, FR-OPS-09, FR-ITM-04, FR-CON-03/04; BA-011/012/031/040/041/053. FE 작성, BE/AI 검토.

### PM-003 · 시간 편집과 날짜 선택 node 오분류

- **차단 / FCR-017.** `527:4085`는 실제 `S07-2 / move-date` 날짜 이동 후 편집 화면이다. 시간 입력기가 아니다. `527:4695`는 “어느 날에 추가할까요?” 후보 일정화 날짜 선택이다.
- [핸드오프](../design/FIGMA_HANDOFF.md)·[기능 인벤토리](../product/FUNCTIONAL_INVENTORY.md)·[소유권](../engineering/OWNERSHIP_MATRIX.md)의 설명을 정정했다. FR-ITM-04/FR-CON-03 시간 입력 node는 미확인으로 남겼다.
- **조치/검증:** 선택 Day와 본문 Day 불일치도 수정한다. 추가 결과 variant의 맨 앞/뒤 삽입 정책을 확정하고 저장 후 재조회 순서/시간을 검증한다.
- **연결:** FR-ITM-02~04, FR-CON-03; BA-040/041. FE node 수정, BE/AI 필드 검토.

### PM-004 · 추천 초안의 확인 전 계약이 없음

- **차단 / REC-CON-04 구체화, FCR-018.** `438:3158`은 날짜 없는 필수 장소 목록이고 `384:5673`은 시작/수정 선택 전 초안이다.
- `createTrip`은 최종 생성이며 `SeedTripItem`은 date/position을 요구한다. [OpenAPI](../api/openapi.yaml)에는 미확정 필수 장소로 초안을 조회·재계산하는 public 계약이 없다.
- **조치:** 초안 생성/만료/수정/확인 API 또는 승인된 브라우저 초안 규칙을 제안한다. LLM 사실 생성과 확인 전 여행 저장은 금지한다. 수동 `438:3199`의 직접 시작 CTA와 확인 화면 경유 여부도 통일한다.
- **연결/검증:** FR-TRC-04/05/08~10/12; BA-000/030, FE 검토. 세 planningLevel, 뒤로/refresh/취소/중복 확인, 확인 전 여행 0. BA-084 P1 AI draft와 분리.

### PM-005 · import가 wizard 입력과 수정 의도를 전달하지 못함

- **차단 / FCR-019.** `ParseImportRequest`에는 선택한 start/end가 없고 `ConfirmImportRequest.title`은 필수인데 제목 UI가 없다. remap에는 오인식 item 제거/전체 날짜 보정 표현이 없다. 응답에서 timezone 복구도 명확하지 않다.
- `401:1221`의 연도 없는 날짜·오전/오후를 임의 확정하면 안 된다. browser-first→createTrip 경로와 server confirm의 IMPORT 잠금 의미도 맞춰야 한다. “마지막 확인 시만 서버 전송”은 서버 parse 보조와 충돌한다.
- **조치:** 날짜 기준·기본 제목·제거 수정·원문 전송 전 안내·TTL/ETag·source를 같은 example에 담는다.
- **연결/검증:** FR-TRC-06~08, NFR-PRV-01; BA-060/030/041, FE 검토. 연도 없음/범위 밖/중복/미해결/제거/응답 유실/24시간 만료·원문 비저장.

### PM-006 · 관심사·동행인 taxonomy가 미정

- **차단 / FCR-020.** `438:3108`은 “누구와”와 스타일 chip을 받지만 `TripInterest`에는 자유 string code와 필수 weight만 있다. 지원 code·KO/EN label·단일/복수 선택·기본 weight가 없다.
- 같은 code에 다른 weight인 두 객체는 uniqueItems를 통과한다. ERD PK `(trip_id, interest_code)`와 맞는 domain 검증이 필요하다. 실제 DB 중복 저장을 관찰한 것은 아니다.
- **조치/검증:** versioned dictionary, companion의 별도 축 여부, 미지원/중복 오류를 결정한다. 모든 chip 매핑·0개/20개 상한·KO/EN 복구를 검증한다.
- **연결:** FR-TRC-02, FR-PRO-05; BA-011/030/031. BE/AI 제안, FE/PM 검토.

### PM-007 · 편집 저장·취소와 복합 command 원자성 공백

- **차단 / FCR-021.** `411:1837` 저장/취소와 `413:2020`의 미저장 변경은 buffer 편집이다. `527:3876` 해제하고 이동과 `413:2081` 해제 후 교체도 하나의 사용자 의도다.
- API는 add/update/delete/reorder/constraint/replace로 분리돼 있다. reorder로 시간·추가·삭제·잠금까지 저장할 수 없고 순차 요청은 중간 실패에 일부 변경을 남긴다.
- **조치:** baseVersion+명령 목록을 한 번에 적용하는 commit 또는 동등한 원자 계약을 제안한다. 즉시 저장 UX를 택하면 취소/폐기/복구도 새로 승인한다.
- **연결/검증:** FR-TRP-02/03, FR-ITM-01~08, FR-CON-05/06; BA-040~042. BE/AI 제안, FE 검토. 혼합 저장·각 쓰기 fault·stale·취소에서 부분 반영 0.

### PM-008 · local time과 JSON Schema time format 충돌

- **차단 / 재현됨.** [API 규칙 §12](../api/README.md)는 offset 없는 local time인데 startTime/suggestedTime 등은 `format: time`이다.
- AJV에서 `09:30`, `09:30:00`은 실패하고 `09:30:00+09:00`은 통과했다. Figma의 09:30을 그대로 보내면 validator별 차이가 생긴다.
- **조치 제안:** 공용 LocalTime을 HH:mm 또는 승인한 초 단위 규격 하나로 고정하고 pattern/길이/examples로 표현한다. timezone·null 제거·DST 중복/누락 시각도 결정한다. 공개 schema는 FE 검토 전 동결하지 않았다.
- **연결/검증:** FR-ITM-04, FR-CON-03/04, FR-TRC-07; BA-004/030/040/041/060. 00:00/23:59 허용, 24:00/offset/잘못된 분 거절, Java↔TS↔DB 왕복. [재현 자료](../contracts/review-2026-09-06/probes.json).

### PM-009 · 후보 상태·교체·REVERT에서 독립 변경 보존 미정

- **차단 / FCR-022.** `412:1912`의 SCHEDULED 후보에도 제거 action이 보이지만 계약은 직접 제거를 거절한다. item REMOVE/RESTORE_CANDIDATE, 교체 전후 후보 linkage·동일 POI 중복 처리를 표로 확정해야 한다.
- 후보 저장/dismiss는 trip version을 올리지 않지만 revision에 candidate linkage가 포함된다. APPLY→독립 후보 변경→REVERT가 과거 aggregate 전체를 복원하면 새 후보 변경을 지울 위험이 있다.
- **조치:** 독립 후보 상태와 일정 종속 linkage를 나누고 복원 범위를 명시한다. 실제 데이터 유실을 관찰한 것이 아니라 구현 전 정책 공백이다.
- **연결/검증:** FR-CAN-04~07, FR-ITM-02/06/07, FR-OPT-09; BA-034/040/042/053, FE 검토. schedule/remove/restore/replace/duplicate matrix와 APPLY 뒤 저장/dismiss 보존.

### PM-010 · 일반 콘텐츠·이미지 출처가 list 응답에서 끊김

- **차단 / FCR-023.** PlaceSummary에 콘텐츠 provenance가 없고 PostSummary.coverUrl은 asset 권리를 전달하지 않는다. MediaAsset은 상세의 선택 field이며 DataProvenance는 주로 crowd/relation에 붙는다.

### PM-017 · 세션 만료와 다중 탭 복구 정책 미정

- **보완.** Privacy는 idle30일과 absolute expiry를 요구하지만 absolute 값, cookie 유실 뒤 복구 불가 안내, owner 자동 삭제 시점이 확정되지 않았다.

- **조치/검증:** expiry/GC/reissue/revocation과 안내를 결정한다. 6회 refresh·6개 tab·idle/absolute 경계·cookie 삭제·owner GC, 401 뒤 mutation 자동 재실행 없음을 검증한다.

### PM-018 · 삭제 receipt의 응답 저장 예외 명시 필요

- **조치/검증:** token 없는 receipt metadata 저장→허용 revoked-cookie retry 때 서명값 재생성, key rotation/TTL을 명시한다. 응답 유실→동일 receipt, DB/cache/log 원문0, 타 route401, job 경쟁/7일 만료를 검증한다.

## 5. 이번 반영과 남은 승인

오기·탐색 링크·source fallback/slot 한도·공식 공지 재확인·FCR 착수/완료 구분·작업별 누락 연결을 반영했다. 사용자 추가 요청에 따라 [#10 기반 결정안](../engineering/FOUNDATION_DECISIONS.md)과 [#11 추가 계약 packet](../contracts/review-2026-09-06/README.md)을 작성했다. OpenAPI 0.2.1-rc.1에 선택 출처/undo 필드, KTO 예시, 최초 결정 응답 union을 제안했고 Compose의 기존 tag를 확인한 digest로 고정했다. 이벤트 shape는 그대로다. FE 교차 검토, 실제 앱/DB/보안/통합 실행과 이슈 종료는 아직 아니다.

다음 계약 packet은 schema/example, node/state, entity 전이, 실패/복구, 담당/검토자, 실제 test 위치를 포함해야 한다. 승인되면 OpenAPI/event→ERD→생성 client→BE/FE 구현 순으로 반영한다.
