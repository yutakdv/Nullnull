## 1. 이번 수정의 결론

현재 Figma의 이미지 중심 Feed, 하단 탭, 카드 톤, My Trip 일정 카드, 전후 비교 화면의 시각 방향은 유지한다. 기능 구조는 아래 한 줄로 통일한다.

```text
Feed·검색·Live에서 발견
→ 여행별 담아둔 장소에 저장
→ My Trip에서 직접 편집하거나 AI 최적화
→ 지도·타임라인·지표로 변경 전후 확인
→ 사용자가 승인한 뒤에만 일정 반영
```

가장 중요한 변경은 `+ = 일정에 즉시 추가`가 아니라 `+ = 선택한 여행의 후보 보관함에 담기`라는 점이다. 확정 일정은 사용자가 수동으로 저장하거나 AI 변경안을 승인했을 때만 바뀐다.

P0와 P1은 공모전 포함 여부가 아니라 구현 순서다.

| 단계 | 디자인·구현 범위 |
|---|---|
| P0 MVP | 후보 저장, My Trip 수동 편집, 독립 잠금, 동일·유사 일정 안내, ITEM 최적화 Preview·승인·되돌리기 |
| P1 공모전 확장 | DAY/TRIP 지도·타임라인 최적화, 실제 경로·시간 지표, opt-in 후보 교체, 전체 일정 생성, Live Re-plan, 검증된 영어·검색·알림·UGC |

공모전 최종 화면 범위는 P0+P1이다. P0가 통과한 뒤 P1 화면을 같은 컴포넌트와 상태 모델로 확장한다.

## 2. 확인한 현재 Figma 틀

- A1~A3: Splash, 언어 선택, 서비스 소개
- Home Feed: 추천/팔로잉/최신 탭, 2열 이미지 카드, 카드 `+`, 일정 미등록 배너
- S03-D: 게시물 상세와 하단 `일정에 담기`
- S02: 여행 날짜, 관심사, 계획 정도, Must Visit 입력, 생성 일정 확인
- S06-1: 장소·날짜·시간·Must Visit/Flexible을 고르는 `일정에 담기` Bottom Sheet
- S07: 날짜별 My Trip 카드와 하트, 카드 안의 날짜 변경 제안
- S09: One Small Change 전후 날짜 비교
- S09-S: 현재 장소와 대체 장소의 교체 비교
- S11: 현재 여행지, 다른 관광지, 장소 상세, `+ 담기`, REPLAY 상태
- Profile·데이터 안내 화면

이 명세는 위 프레임을 삭제하고 새로 시작하는 지시가 아니다. 기존 프레임을 Variant와 연결 화면으로 확장하는 지시다.

## 3. 화면 전체에 적용할 용어와 상태

### 3.1 사용자 용어

| 내부 개념 | 화면 문구 | 의미 |
|---|---|---|
| SavedPost | 저장 | 여행과 무관한 게시글 북마크 |
| TripCandidate | 담아둔 장소 | 특정 여행에 속하지만 날짜·시간이 정해지지 않은 후보 |
| TripItem | 내 일정 | 날짜·시간·순서가 확정된 일정 항목 |
| Manual Edit | 일정 편집 | 사용자가 직접 추가·삭제·교체·잠금 수정 |
| Optimization | AI로 일정 최적화 | 서버가 계산한 변경안을 사용자가 검토·승인 |

`저장`과 `내 여행에 담기`를 같은 아이콘이나 같은 완료 문구로 처리하지 않는다. 카드 `+`의 접근성 라벨은 `○○ 여행의 담아둔 장소에 추가`처럼 목적을 명시한다.

### 3.2 잠금

한 항목에 아래 값을 독립적으로 설정한다.

- `♥ Must Visit`: 목적지를 유지한다.
- `날짜 고정`: 다른 날짜로 옮기지 않는다.
- `시간 고정`: 시작 시간대를 바꾸지 않는다.
- `예약 고정`: 예약에서 온 강한 잠금이다. 출처를 표시하고 해제 시 추가 확인을 거친다.

하트는 현재 Figma의 Must Visit 표현을 유지한다. 날짜·시간은 별도 토글 또는 잠금 칩으로 표시한다. 하트 하나로 날짜·시간까지 모두 잠긴 것처럼 보이면 안 된다.

### 3.3 AI 역할 표시

사용자 화면 명칭은 `AI로 일정 최적화`를 사용한다. 다만 설명 영역에는 다음 의미가 드러나야 한다.

- AI는 선호와 변경 이유를 설명한다.
- 운영 여부, 혼잡, 경로, 도착 가능 시간은 출처가 있는 데이터와 서버 규칙이 검증한다.
- 승인 전에는 일정을 바꾸지 않는다.

## 4. 화면별 수정 지시

### D-01. Home Feed와 게시물 상세

#### 유지

- 현재 추천/팔로잉/최신 탭과 이미지 중심 카드 레이아웃
- 일정 미등록 배너의 위치와 `일정 등록하기 / 일단 둘러보기`
- 공식 관광정보 기반 카드의 현재 비주얼 톤

#### 수정

1. 카드 `+`와 S03-D 하단 CTA의 의미를 `담아둔 장소에 추가`로 변경한다.
2. 등록된 여행이 여러 개면 작은 여행 선택 Bottom Sheet를 연다.
3. 활성 여행이 하나면 바로 담고 `○○ 여행에 담았어요` Toast를 보여준다.
4. 완료 상태는 `✓ 담음` 또는 채워진 `+` Variant로 바꾸되 날짜·시간을 표시하지 않는다.
5. 게시글 북마크가 있다면 `저장` 아이콘을 `+`와 분리한다.
6. 일정 기반 추천 이유는 등록 일정이 있을 때만 표시한다.

#### 필요한 상태 프레임

| 프레임 | 내용 | 주 액션 |
|---|---|---|
| `S03-F0 / no-trip` | 현재 일정 미등록 배너 | 일정 등록하기 |
| `S03-F1 / active-trip` | 현재 여행명·기간 + 개인화 이유 | 카드 담기 |
| `S03-C1 / choose-trip` | 담을 여행 선택 | 이 여행에 담기 |
| `S03-C2 / saved` | 담기 완료 Toast/카드 상태 | My Trip에서 보기 |
| `S03-C3 / duplicate` | 이미 담긴 장소 | 담아둔 장소 보기 |
| `S03-C4 / error` | 저장 실패, 카드 원상 유지 | 다시 시도 |

#### 문구

- CTA: `내 여행에 담기`
- 성공: `서울 가을 여행의 담아둔 장소에 추가했어요.`
- 일정 없음: `먼저 여행을 만들면 장소를 담아둘 수 있어요.`
- 중복: `이미 이 여행에 담아둔 장소예요.`

### D-02. S02 일정 등록·확인

현재 `계획 없음 / Must Visit만 있음 / 거의 계획됨` 분기를 첫 질문으로 쓰지 않는다. 첫 분기는 아래처럼 단순화한다.

```text
이미 일정이 있어요
→ 텍스트 붙여넣기 / .txt·.csv·.xlsx 업로드 / 직접 입력

아직 일정이 없어요
→ 지역 / 날짜 / 관심사 / 선택적 Must Visit
→ Feed 먼저 보기 또는 AI 일정 만들기(P1)
```

#### 일정 확인 화면

- 여행 기간과 장소
- 추출·선택 관심사와 근거
- Must Visit 후보
- 날짜 고정·시간 고정·예약 고정
- 변경 가능한 항목
- 빈 시간
- 인식이 불완전한 항목과 직접 수정

붙여넣기·파일·직접 입력은 모두 하나의 확인 화면으로 모은다. 사용자가 확정하기 전에는 TripItem으로 저장된 것처럼 표현하지 않는다.

현재 생성 일정 프레임은 폐기하지 않는다. P1의 `AI 일정 만들기` 결과 화면으로 바꾸고, S09와 같은 지도·타임라인·승인 패턴을 사용한다. 단순히 `향후 기능`으로만 남겨두지 않는다.

### D-03. S06 `내 여행에 담기` Bottom Sheet

현재 S06-1의 날짜·시간·Must Visit 선택 폼은 기본 화면이 아니라 선택적 2단계로 이동한다.

#### 1단계 — 기본 저장

- 장소 썸네일·이름·지역
- 담을 여행 선택
- 추천 이유 또는 출처
- Primary: `담아두기`
- Secondary text action: `바로 일정에 배치`

`담아두기`는 날짜·시간을 요구하지 않는다. 완료 후 TripCandidate만 생성한다.

#### 2단계 — 사용자가 `바로 일정에 배치`를 선택한 경우

- 날짜
- 시작 시간
- 예상 소요시간
- Must Visit
- 날짜 고정
- 시간 고정
- 겹치는 일정과 이동 가능성
- Primary: `일정에 배치하기`

날짜·시작 시간을 정하지 않으면 `일정에 배치하기`를 완료하지 않고 TripCandidate로 유지한다.

#### 필요한 상태

- 정상 저장
- 여행 없음
- 이미 담음
- 이미 확정 일정에 있음
- 시간 충돌
- 경로 확인 불가
- 저장 실패
- 완료 + `My Trip에서 보기`

`이미 일정에 있음`에서는 중복 추가 버튼을 없애고 `기존 일정 보기`와 `담아둔 장소에서 제거`만 제공한다.

### D-04. S07 My Trip — 기본 보기

#### 상단 구조

- 여행명·기간·여행 선택
- `담아둔 장소 n`
- Secondary: `일정 편집`
- Primary: `AI로 일정 최적화`
- 날짜 탭 또는 Day selector

버튼 순서는 화면 폭에 따라 달라도 되지만 `일정 편집`과 `AI로 일정 최적화`를 한 메뉴 안에 숨기지 않는다.

#### 일정 카드

- 시간, 장소명, 소요시간
- `♥ Must Visit`, `날짜 고정`, `시간 고정`, `예약` 상태 요약
- 혼잡 상태·근거·기준시각
- 카드 메뉴: `직접 수정`, `이 항목 최적화`

현재 카드 안의 날짜 변경 제안은 자동 적용처럼 보이지 않게 `더 여유로운 날짜가 있어요 · 비교하기`로 바꾸고 S09 ITEM Preview로 연결한다.

### D-05. S07 My Trip — 일정 편집 모드

`일정 편집`을 누르면 상단 제목 또는 mode bar에 `편집 중`을 명확히 표시한다.

#### 편집 가능 항목

- 날짜·시작 시간·예상 소요시간
- 드래그 또는 명시적 위/아래 이동으로 순서 변경
- Must Visit on/off
- 날짜 고정 on/off
- 시간 고정 on/off
- 일정 삭제
- 담아둔 장소 추가
- 담아둔 후보로 기존 항목 교체

#### 하단 고정 액션

- `취소`
- `변경 n개 저장`

미저장 변경이 있을 때 뒤로 가기·탭 이동을 하면 `변경 내용을 버릴까요?` 확인을 제공한다. 저장 실패 시 편집값을 유지한다.

#### 담아둔 장소 패널

모바일은 Bottom Sheet, 데스크톱은 오른쪽 Drawer를 기본으로 한다. 화면 구현 여건에 따라 형태는 바꿀 수 있지만 일정과 후보를 동시에 비교할 수 있어야 한다.

후보 카드 공통 요소:

- 장소명·이미지·카테고리·출처
- 추천 이유
- 현재 일정과의 관계 배지
- `일정에 추가` 또는 `교체 검토`
- `담아둔 장소에서 제거`

| 상태 | 표시 | 허용 액션 |
|---|---|---|
| EXACT | `이미 Day 2 일정에 있어요` | 기존 일정 보기, 후보 제거 |
| SIMILAR | `Day 2의 성수 카페거리와 비슷해요` + 이유 | 기존 장소와 교체, 둘 다 유지 |
| NONE | `현재 일정과 겹치지 않아요` | 일정에 추가 |
| CHECKING | Skeleton + `일정과 비교 중` | 적용 버튼 비활성 |
| UNKNOWN | `비슷한 일정 여부를 확인하지 못했어요` | 직접 비교 후 추가 |

SIMILAR은 자동 교체가 아니다. `기존 장소와 교체할까요?` 확인 화면에서 현재 항목과 후보를 나란히 보여주고 사용자가 선택한다.

Must Visit 교체를 사용자가 시작하면 먼저 `Must Visit 잠금을 해제해야 교체할 수 있어요`를 보여준다. 예약 고정이면 예약 출처와 영향도 함께 표시한다.

### D-06. S09 AI 일정 최적화 Preview

현재 One Small Change와 장소 교체의 전후 비교 틀을 하나의 S09 컴포넌트 계열로 합친다.

#### 진입 설정

- 범위 Segmented control: `이 장소 | 오늘 | 전체 여행`
- `담아둔 대안도 포함` Toggle — 기본 OFF
- 고정 조건 요약: `Must Visit 2 · 날짜 고정 1 · 시간 고정 3 · 예약 1`
- `최적화 시작`

현재 화면에 보이는 일정만 기본 입력으로 사용한다. `전체 여행`을 사용자가 직접 골랐을 때만 모든 Day를 계산한다.

#### Loading

- `이동 경로와 시간 조건을 확인하고 있어요.`
- 계산 단계: 일정 확인 → 혼잡·운영 검증 → 경로 계산 → 변경안 구성
- 취소 또는 My Trip으로 돌아가기

#### Preview 상단

- 제목: `이렇게 바꾸면 어때요?`
- 상태: `아직 일정에 반영되지 않았어요`
- 변경 수와 영향 범위
- 근거 기준시각·데이터 상태

#### 변경 전후 지도

DAY/TRIP에서 유효한 route matrix가 있을 때만 표시한다.

- Before / After 토글 또는 좌우 비교
- 같은 지도 viewport와 scale
- 방문 순서 번호
- 변경된 구간 강조
- 경로가 없는 ITEM Preview에서는 지도를 억지로 만들지 않고 날짜·시간 비교를 우선한다.
- 지도 실패 시 일정 목록은 유지하고 `경로를 확인하지 못해 전체 최적화안을 적용할 수 없어요`를 표시한다.

#### 타임라인과 지표

- 날짜별 Before / After 타임라인
- 이동·교체·추가·삭제를 서로 다른 라벨로 구분
- 총 이동시간
- 총 이동거리
- 대기·빈 시간
- 피크 혼잡 일정 수 또는 비교 가능한 CrowdLevel 변화
- 바뀐 항목 수

숫자는 데이터가 검증된 항목만 표시한다. `약 40분 단축`처럼 경로 근거 없는 값을 만들지 않는다.

#### 하단 액션

- Primary: `변경 n개 적용`
- Secondary: `현재 일정 유지`
- Tertiary: `조건 다시 설정`

적용 후 Toast: `일정을 업데이트했어요 · 되돌리기`. `되돌리기`는 명확한 시간창 또는 다음 변경 전까지 제공한다.

#### 오류·충돌 Variant

| 상태 | 문구 | 액션 |
|---|---|---|
| TRIP_CHANGED | `다른 곳에서 일정이 바뀌었어요.` | 최신 일정으로 다시 계산 |
| DATA_CHANGED | `최신 혼잡 정보에서 개선 방향이 달라졌어요.` | 다시 계산 |
| LOCK_CONFLICT | `고정한 일정과 충돌해 적용할 수 없어요.` | 고정 조건 보기 |
| ROUTE_UNAVAILABLE | `경로를 확인하지 못했어요.` | 현재 일정 유지 / 다시 시도 |
| NO_IMPROVEMENT | `현재 일정이 조건 안에서 가장 적합해요.` | My Trip으로 돌아가기 |
| APPLY_FAILED | `일정은 바뀌지 않았어요.` | 다시 시도 |

### D-07. S09-S 장소 교체

현재 장소 교체 비교 프레임은 삭제하지 않고 S07 수동 편집과 S09 opt-in 교체가 함께 재사용하는 `Place Compare` 컴포넌트로 바꾼다.

- 왼쪽/위: 현재 일정 항목
- 오른쪽/아래: 담아둔 후보
- 유사 판정 이유
- 날짜·시간·이동·혼잡·운영 차이
- 유지되는 잠금과 해제되는 잠금
- 수동 경로 CTA: `이 장소로 교체`
- AI Preview 안 CTA: 별도 즉시 교체 버튼 없이 전체 `변경 n개 적용`에 포함

### D-08. S10 주변·연관 장소

- 범용 `비슷해요` 배지를 자동 생성하지 않는다.
- 검수된 relation이 있을 때만 `현재 일정의 ○○와 비슷한 경험`과 이유를 표시한다.
- `+`는 TripCandidate 저장이다.
- 기존 일정과 SIMILAR이면 저장 후 My Trip에서 교체 검토로 연결한다.
- 비교 근거가 없으면 장소 자체 정보만 보여주고 우열 화살표를 제거한다.

### D-09. S11 Live·REPLAY

현재 탭·카드·상세 구조는 유지하고 아래 액션을 바꾼다.

- `+ 담기` → 선택한 여행의 TripCandidate 저장
- 장소 상세 CTA → `내 여행에 담기`
- 현재 또는 다음 일정의 혼잡 악화 시 → `오늘 일정 최적화`로 S09 `scope=DAY` 진입
- Live Re-plan도 바로 일정을 수정하지 않고 Preview를 만든다.

REPLAY 화면은 `과거 관측 재생 · 실시간 아님`과 원 관측시각을 Header·카드·상세에서 유지한다. REPLAY에서 담은 후보도 데이터 출처를 보존하되 현재 실시간 추천처럼 표현하지 않는다.

### D-10. 알림·Profile·데이터 안내

#### 알림

- `작은 변경안을 확인하세요` → `일정 최적화안을 확인하세요`
- 알림은 정확한 Trip의 Optimization Preview로 이동
- 알림을 눌렀다는 이유만으로 적용하지 않음

#### Profile

- 내 여행별 `담아둔 장소 n`
- Trip별 관심사·일정 신호 관리
- AI 최적화 이력은 `적용/유지/되돌림` 상태만 표시하고 민감한 일정 원문은 노출하지 않음

#### 데이터 안내

- TripCandidate와 확정 일정의 차이
- Must Visit·날짜·시간·예약 잠금의 차이
- AI와 결정적 검증 로직의 역할 경계
- 승인 전 일정 불변 원칙
- Live/Forecast/REPLAY와 경로 데이터의 출처·기준시각

## 6. 프로토타입 연결

### P0 핵심 경로

```text
Home 카드 +
→ 여행 선택
→ 담기 완료
→ My Trip
→ 일정 편집
→ 담아둔 장소 패널
→ SIMILAR 교체 비교
→ 변경 저장
```

```text
My Trip 카드 `이 항목 최적화`
→ S09 ITEM Preview
→ 현재 일정 유지 또는 변경 적용
→ 적용된 My Trip
→ 되돌리기
```

### P1 공모전 경로

```text
My Trip `AI로 일정 최적화`
→ 범위 DAY/TRIP + 후보 포함 OFF
→ Loading
→ 지도·타임라인·지표 Preview
→ 변경 n개 적용
→ My Trip
```

```text
Live `오늘 일정 최적화`
→ S09 DAY Preview
→ 사용자 승인
→ 업데이트된 오늘 일정
```

각 경로에 `취소`, `뒤로`, `오류`, `빈 상태` 연결도 만든다. 성공 경로만 이어 놓지 않는다.

## 7. 반응형·접근성

- 360px: 후보 패널과 비교 화면은 Bottom Sheet 또는 세로 스택
- 768px: 타임라인과 후보 패널을 화면 안에서 함께 비교 가능
- 1280px 이상: 일정 목록 + 후보 Drawer, 또는 지도 + 타임라인 2열
- 지도 색상만으로 Before/After나 혼잡을 구분하지 않는다.
- 잠금 토글은 아이콘·색상뿐 아니라 텍스트 상태를 제공한다.
- 드래그 정렬에는 `위로 이동 / 아래로 이동` 키보드 대안을 제공한다.
- 모든 Sheet·Dialog는 제목, 초기 포커스, 닫기, Esc, 포커스 복귀를 정의한다.
- 적용 버튼에는 `변경 4개 적용`처럼 결과를 명시한다.
- 영어 문자열 길이에서도 버튼·배지·탭이 잘리거나 의미가 생략되지 않게 Auto Layout을 사용한다.

## 9. 디자인 완료 체크리스트

- [ ] Feed·검색·Live의 `+`가 모두 TripCandidate 저장으로 표현된다.
- [ ] 북마크 저장과 여행 후보 담기가 시각·문구상 구분된다.
- [ ] 일정이 없거나 여행이 여러 개인 경우의 여행 선택 상태가 있다.
- [ ] S06 기본 상태는 날짜 없는 `담아두기`이고 즉시 배치는 선택적 2단계다.
- [ ] S07에 `일정 편집`, `AI로 일정 최적화`, `담아둔 장소 n` 진입점이 동시에 보인다.
- [ ] Must Visit·날짜 고정·시간 고정·예약 고정이 독립적으로 보인다.
- [ ] 후보 EXACT/SIMILAR/NONE/CHECKING/UNKNOWN 상태가 있다.
- [ ] SIMILAR 후보는 교체/유지를 묻고 자동 교체하지 않는다.
- [ ] 수동 편집의 취소·변경 수 저장·미저장 이탈 상태가 있다.
- [ ] S09에 ITEM/DAY/TRIP 범위와 후보 포함 기본 OFF가 있다.
- [ ] AI Preview에 승인 전 일정 불변 문구, 변경 목록, 적용/유지가 있다.
- [ ] DAY/TRIP에 같은 scale의 전후 지도, 타임라인, 검증된 이동·혼잡 지표가 있다.
- [ ] TRIP_CHANGED, DATA_CHANGED, LOCK_CONFLICT, ROUTE_UNAVAILABLE, NO_IMPROVEMENT 상태가 있다.
- [ ] 적용 후 되돌리기 상태가 있다.
- [ ] Live Re-plan이 S09 DAY Preview를 거치며 직접 변경하지 않는다.
- [ ] REPLAY와 현재 Live가 색상·문구·관측시각으로 구분된다.
- [ ] 키보드·스크린리더·색상 비의존·영문 길이 대응이 정의돼 있다.
- [ ] P0와 P1 프로토타입 경로가 각각 처음부터 끝까지 연결돼 있다.

## 10. 개발 전달 시 함께 내보낼 것

- Figma Dev Mode에서 화면별 상태 코드와 component property
- P0/P1별 프로토타입 시작점 URL
- 사용 문구 목록과 번역 key 제안
- 아이콘 의미표: 저장, 담기, Must Visit, 날짜 고정, 시간 고정, 예약 고정
- 지도·경로 provider가 확정되기 전/후 Variant
- 화면별 empty/loading/error/stale 캡처

디자인 완료 후 최종 배포 화면과 이 명세를 다시 대조하고, 달라진 레이아웃은 기획안의 표현을 화면에 맞춰 동기화한다. 후보와 확정 일정의 분리, 독립 잠금, 승인 전 일정 불변, 출처·기준시각은 레이아웃 재량으로 제거할 수 없는 기능 계약이다.
