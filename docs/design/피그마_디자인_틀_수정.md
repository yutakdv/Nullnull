> 대상 시안: [Nullnull — Wireframes](https://www.figma.com/design/C3tTNClo9JH8tb4qpQgP61/Nullnull-%E2%80%94-Wireframes?node-id=72-243&p=f)
>
> 작성일: 2026-08-30
>
> 상태: 디자인 틀 컨펌용

## 1. 문서 목적

이 문서는 현재 피그마의 색상·타이포그래피·카드 형태를 다시 설계하기 위한 문서가 아니다. 서비스가 화면에서 어떤 순서와 의미로 보이는지만 확정한다.

- 유지: 현재 비주얼 방향, 모바일 카드형 Feed, 하단 탭, My Trip의 하트 표시, 날짜 변경·장소 교체의 기본 화면 형태
- 수정: 일정 미등록 안내, 일정 등록 진입 구조, 파일 업로드 진입, 일정 확인 단계, 전체 추천 일정의 연결 위치, 공식 Seed 표시, `+Trip` 상태
- 별도 기획안 반영: 날짜 변경의 충돌·최신 데이터 재검증·되돌리기 같은 비즈니스 규칙

## 2. 확정 수정 항목

### D-01. Home의 일정 미등록 안내

**현재**

- 첫 화면에서 여행 Feed가 바로 보인다.
- 등록된 일정이 없다는 상태와, 일정을 등록했을 때 무엇이 달라지는지가 명확하지 않다.

**수정**

- Feed를 그대로 유지하면서 첫 화면 안에 작은 안내 영역을 추가한다.
- 전체 화면 팝업이나 일정 등록 강제 화면은 사용하지 않는다.

**권장 문구**

- 상태: `등록된 일정 없음`
- 제목: `여행 일정이 아직 없어요`
- 설명: `일정을 등록하면 날짜와 관심사에 맞춰 Feed가 달라져요.`
- Primary CTA: `일정 등록하기`
- Secondary CTA: `일단 둘러보기`

일정 등록 후에는 같은 위치에 현재 여행명·기간과 일정 기반 개인화 안내를 표시한다.

### D-02. 일정 등록의 첫 분기

**현재**

- 여행 날짜, 관심사, 계획 정도를 순서대로 묻고 `계획 없음 / Must Visit만 있음 / 거의 계획됨`으로 분기한다.

**수정**

- 가장 먼저 일정 보유 여부를 선택한다.

```text
이미 일정이 있어요
→ 붙여넣기 / 파일 업로드 / 직접 입력

아직 일정이 없어요
→ 지역 / 날짜 / 관심사 / 선택적 Must Visit
```

- 두 경로는 모두 일정 확인 단계 이후 Feed로 이동한다.
- 일정이 없는 경로를 예외나 보조 기능처럼 표현하지 않는다.

### D-03. 기존 일정 가져오기 방식

**현재**

- 직접 일정 작성과 Must Visit 입력은 있으나 기존 파일을 가져오는 진입점이 없다.

**수정**

- 일정이 있는 사용자의 시작 화면에 다음 세 가지 선택지를 함께 둔다.

1. `텍스트 붙여넣기`
2. `파일 업로드`
3. `직접 입력`

- 파일 업로드 카드에는 P0 지원 형식인 `.txt`, `.csv`, `.xlsx`를 안내한다.
- 시트 선택, 열 매핑, 파싱 규칙, 보안 제한은 디자인 문서가 아니라 기획안에서 관리한다.

### D-04. 일정 확인 단계 통합

**현재**

- 계획 정도에 따라 Must Visit 입력, 직접 일정 작성, 추천 일정 초안 등 서로 다른 결과 화면으로 이동한다.

**수정**

- 붙여넣기·파일 업로드·직접 입력 결과를 하나의 `일정 확인` 단계로 모은다.
- 이 화면에서는 다음 내용을 사용자가 확인하고 수정할 수 있게 한다.

  - 여행 기간과 장소
  - 관심사
  - 하트로 표시되는 Must Visit
  - 변경 가능한 일정
  - 빈 시간
  - 인식이 불완전해 확인이 필요한 항목

- 일정이 없는 경로는 사용자가 직접 선택한 지역·날짜·관심사만 간단히 확인한다.

### D-05. 전체 추천 일정 초안의 위치

**현재**

- 일정이 없거나 Must Visit만 있는 사용자에게 전체 추천 일정 초안이 기본 흐름처럼 연결된다.

**수정**

- 현재 디자인 프레임은 미래 확장안으로 보존한다.
- 공모전 핵심 프로토타입에서는 전체 추천 일정 초안으로 연결하지 않고 일정 확인 후 Feed로 이동한다.
- 프레임에는 `향후 기능 · 전체 일정 생성`이라고 표시해 현재 핵심 흐름과 구분한다.

### D-06. Feed의 공식 Seed 표시

**현재**

- 카드가 실제 사용자 게시물처럼 보일 수 있고 공식 관광정보 기반 콘텐츠인지 구분이 약하다.

**수정**

- 카드 또는 게시물 상세에 `공식 관광정보 기반`을 표시한다.
- 현재 카드 구조와 이미지 중심 레이아웃은 유지한다.
- 사용자 게시물 작성·팔로우 기능처럼 보이는 추가 설명은 넣지 않는다.

### D-07. 일정 기반 추천 이유

**현재**

- Feed가 일정에 맞게 개인화됐다는 근거가 카드에서 충분히 드러나지 않는다.

**수정**

- 일정이 등록된 경우에만 카드 또는 게시물 상세에 짧은 추천 이유를 표시한다.

**예시**

- `등록한 일정의 역사 관심사와 잘 맞아요.`
- `9월 14일 오후 빈 시간에 추가할 수 있어요.`

- 별도의 Feed 화면을 새로 만들거나 Home 전체를 다른 후보로 필터링하지 않는다.

### D-08. `+Trip` Bottom Sheet 상태

**현재**

- 장소와 날짜를 선택해 일정에 추가하는 기본 Bottom Sheet가 있다.

**수정**

- Bottom Sheet의 기본 틀은 유지하고 다음 상태를 같은 컴포넌트의 변형으로 준비한다.

| 상태 | 화면에서 보여줄 내용 |
|---|---|
| 정상 추가 | 여행·날짜·시간대 선택과 `일정에 추가하기` |
| 일정 없음 | `아직 등록된 여행이 없어요`와 `일정 등록하기` |
| 중복 | `이미 일정에 있는 장소예요`와 `기존 일정 보기` |
| 시간 충돌 | 겹치는 일정 안내와 `시간 미정으로 추가`·`다른 날짜 선택` |
| 기존 장소와 교체 | 교체할 일정 선택과 변경 전후 확인 |
| 완료 | 추가 또는 교체 결과와 `My Trip에서 보기`·`되돌리기` |

- 각 상태를 모두 별도 페이지로 만들 필요는 없다. Bottom Sheet 컴포넌트의 상태 프레임으로 관리한다.

### D-09. My Trip의 하트 의미

**현재**

- My Trip에서 하트가 Must Visit을 의미하도록 이미 표시돼 있다.

**확정**

- 현재 하트 표시를 그대로 사용한다.
- 새로운 잠금 아이콘으로 바꾸지 않는다.
- 첫 안내나 범례에서만 `♥ 꼭 가기`처럼 의미를 한 번 명시할 수 있다.
- 하트가 있는 장소도 날짜 변경 화면에는 등장할 수 있지만, 장소 교체 대상에서는 잠금 해제 전까지 선택할 수 없게 표현한다.

### D-10. 장소 교체 진입 방식

**현재**

- 장소 교체 화면이 있으며 사용자가 기존 일정과 새 후보를 비교할 수 있다.

**확정·보완**

- 메인 Home Feed 전체를 대체 관광지만 보이도록 필터링하지 않는다.
- 사용자가 아래 행동 중 하나를 했을 때만 교체 후보를 집중해서 보여준다.

```text
My Trip의 변경 가능한 일정에서 `바꾸기`
또는
Feed 카드의 `기존 장소와 바꾸기`
```

- `바꾸기` 이후 후보 목록은 해당 일정에 맞는 장소만 보여주는 전용 목록으로 사용할 수 있다.
- 하트가 있는 Must Visit은 잠금 해제 전까지 선택 불가 상태로 표시한다.
- 최종 확인 전에는 기존 일정이 변경된 것처럼 표시하지 않는다.

## 3. 현재 디자인에서 유지하는 내용

- My Trip의 하트 = Must Visit 표현
- S09 날짜 변경의 변경 전·후 비교 구조
- S09-S 장소 교체의 사용자 선택 구조
- Feed의 이미지 중심 카드 레이아웃
- Home Feed를 일정 등록 전에 먼저 둘러볼 수 있는 구조
- 하단 `Home / My Trip / Live / Profile` 탐색 틀

## 4. 이번 디자인 컨펌에서 제외하는 내용

날짜 변경의 충돌 검사·최신 데이터 재검증·적용 실패·되돌리기는 화면 틀 수정이 아니라 기능 규칙이므로 이 목록에서 제외하고 기획안 S09에서 관리한다. 그 밖의 개발 우선순위와 구현 세부사항도 이번 디자인 수정 목록에는 포함하지 않는다.

## 5. 디자인 반영 완료 체크

- [ ] Home 첫 화면에 일정 미등록 안내와 CTA가 있다.
- [ ] 일정 등록 첫 단계가 `일정 있음 / 일정 없음`으로 나뉜다.
- [ ] 일정 있음 경로에 붙여넣기·파일 업로드·직접 입력이 있다.
- [ ] 모든 일정 입력 방식이 하나의 일정 확인 단계로 모인다.
- [ ] 전체 추천 일정 초안이 현재 핵심 프로토타입에서 분리돼 있다.
- [ ] 공식 관광정보 기반 카드임을 확인할 수 있다.
- [ ] 일정 등록 후 추천 이유를 확인할 수 있다.
- [ ] `+Trip`의 주요 상태가 같은 Bottom Sheet 변형으로 정의돼 있다.
- [ ] My Trip 하트가 Must Visit 의미로 일관된다.
- [ ] 장소 교체는 사용자가 `바꾸기`를 시작한 뒤 전용 후보 목록으로 이어진다.
