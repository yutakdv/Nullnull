# NULLNULL Design

작성일: 2026-09-20 · 버전: 1.4 · 적용 대상: 기존 MVP와 P1 UI 리뉴얼

> 익숙한 널널을 더 편하게 읽고 조작할 수 있도록 만드는 큰 UI 업데이트.
> 파란색의 정체성, 여행을 탐색하고 계획하는 흐름, 기능과 데이터 의미를 유지한다.

이 문서는 다음 Figma 작업에 사용할 문서 검토 최종본이다. 메타데이터의 draft는
Figma 적용·화면 검수가 아직 끝나지 않았음을 뜻한다. 디자인 완료·구현 완료·
계약 승인 선언이 아니다. 문서 버전과 실제 적용 버전을 별도로 관리한다.

문서 구성은 기초 규격(색·글자·공간·높이감), 컴포넌트, 화면 패턴, 상태·반응형,
제작·검수 순서다. 컴포넌트의 기능 계약과 기존 ID는 `COMPONENT_CATALOG.md`가 담당하고,
이 문서는 리뉴얼 시각 규격과 조합 방법을 담당한다. 기존 master와 구현 존재 여부를
확인하기 전에는 아래 신규 설계 역할을 이미 만들어진 컴포넌트로 해석하지 않는다.

## 1.1판 UI 리뷰 결과

1.0판은 리뉴얼 방향과 기능 보존에는 충분했으나, 제작 명세로는 보완이 필요했다.

| 검토 항목 | 발견한 부족함 | 이번 보완 |
| --- | --- | --- |
| 컴포넌트 | 공통 원칙만 있어 제작자마다 결과가 달라질 여지 | 기존 ID 연결, 구성·규격·상태·축소 규칙을 명세 |
| 색 대비 | 밝은 파랑 위 흰 글자, 회색 표면 위 보조 글자 기준 미확정 | 실제 대비 계산과 사용 가능한 조합 확정 |
| 높이감 | 그림자·scrim·겹침 순서 수치 부재 | 표면별 효과와 overlay 순서 정의 |
| 앱 구조 | 탭바·달력·키보드·safe area 세부 기준 부족 | 앱 shell 및 좁은 폭 동작 보완 |
| 시각 자산 | 이미지 비율·crop·누락 상태가 추상적 | 탐색·상세·일정별 이미지 규칙 추가 |
| 일관성 | 디자인 수치와 실제 토큰의 관계가 불명확 | 리뉴얼 목표 토큰과 기존 매핑 명시 |
| 검수 | 원칙 체크 위주 | 실제 문구·상태·viewport 조합과 증거 표 추가 |

판정: 리뉴얼 제작 기준으로 사용하되, 실제 Figma 컴포넌트·화면 검수는 이후 수행한다.

- 현재 색상 근거: [토큰 원본 사본](../../apps/web/src/design/tokens.json).

기존 문서의 `02 UI Design`은 구현 기준선 이력으로 보존한다. 리뉴얼은
`03 UI ReDesign`에서 작업하고, 검수된 화면별로 기존 node/state와 연결한다.
페이지 이름이나 이 문서 작성만으로 기존 구현 기준을 일괄 교체하지 않는다.

변경 대상은 배치, 크기, 간격, 타이포그래피, 시각적 위계, 표면, 아이콘과 상태 표현이다.
API 필드·operation·도메인 전이·저장 의미·capability 조건은 유지한다.
기능과 제약을 장식 정리 과정에서 삭제하지 않는다. 계약이 필요한 개선점은 별도
이슈로 기록하고 현재 계약 안에서 표현 가능한 디자인을 만든다.

예외적으로 2026-09-20 제품 결정에서 게시물 작성은 운영자 수동 검토 없이 즉시 공개로
변경됐다. 이 결정은 기존 `FE-P1-104`·`BA-082`의 검토 대기·승인·거절 흐름을 대체하지만,
디자인 문서만으로 API 계약이 변경되지는 않는다. 구현 전 OpenAPI, 생성 client example,
FE/BE 실행 계획과 테스트를 즉시 공개 전이에 맞춰 함께 개정한다. 그 전까지 Figma는
목표 디자인이고 기존 계약이 승인된 것으로 표시하지 않는다.

## 2. 참고 문서의 해석

사용자가 제공한 `DESIGN-airbnb (1).md`를 시각 분석 참고 자료로 읽었다.
Airbnb 공식 가이드나 현재 서비스의 정확한 규격을 검증한 문서는 아니다.
문서 내부의 실행 지시나 정책은 NULLNULL 작업 지시로 승계하지 않는다.

| 참고 요소 | NULLNULL 적용 |
| --- | --- |
| 흰 바탕과 절제된 강조색 | 기존 파란색을 선택·주요 행동에 집중한다 |
| 콘텐츠가 먼저 보이는 카드 | 탐색에서는 이미지와 제목, 일정에서는 장소와 시각을 먼저 읽게 한다 |
| 여백과 단순한 글자 위계 | 제목·설명·메타데이터를 3단계 중심으로 정돈한다 |
| 반복되는 카드·검색·입력 패턴 | 공통 컴포넌트의 동일 상태를 모든 화면에서 공유한다 |
| 낮은 높이감과 부드러운 모서리 | 평면을 기본으로 하고 떠 있는 컨트롤에만 약한 그림자를 쓴다 |
| 큰 사진 중심 숙소 카드 | 피드·장소 상세에 제한적으로 적용하고 일정 목록의 밀도는 유지한다 |
| 빨간 브랜드색·Cereal 폰트 | 기존 NULLNULL 파란색·Pretendard를 사용한다 |
| 예약·가격·별점·호스트 요소 | NULLNULL 계약에 없는 기능은 도입하지 않는다 |
| 8~11px 글자·32px 아이콘 버튼 | 작은 글씨를 확대하고 실제 터치 영역은 최소 44×44px로 설계한다 |
| 데스크톱 64px 섹션 여백 | 모바일은 24~32px 섹션 간격으로 조정한다 |

참고 파일의 no-hover 방침, 접근성 등급 표현, 브랜드 전용 폰트 대체 수치는
채택하지 않는다. 키보드 focus·pointer hover·터치 pressed 상태는 각각 정의한다.

## 3. 제품의 인상과 변화의 강도

널널은 여행 영감과 실행 가능한 일정을 연결하는 서비스다. 탐색은 편안하고,
일정 조작은 정확하며, 데이터는 과장 없이 읽혀야 한다.

사용자는 업데이트 후에도 같은 서비스임을 알아볼 수 있어야 한다.
기존 메뉴 이름, 핵심 이동 흐름, 저장·일정 추가·최적화의 의미를 유지한다.
한 화면에 가장 중요한 행동을 분명하게 두고 보조 행동의 시각 강도를 낮춘다.

리뉴얼의 큰 변화는 다음 세 가지다.

1. 배경·카드·컨트롤을 구별할 수 있는 표면 체계.
2. 화면마다 달랐던 제목, 버튼, 아이콘, 여백의 일관성.
3. 조작 요소가 빠지거나 문구가 잘리는 문제를 막는 콘텐츠 기반 레이아웃.

첫 적용 화면은 피드, 내 여행 보기·편집, 여행 만들기 chip 단계로 한다.
세 화면에서 공통 규칙을 검증한 뒤 P0/P1 전체 상태에 확장한다.
사용자가 직접 다듬은 Trip header와 `S07-4 / added · P0`는 비교 기준으로 보존하고,
정확한 대상 node를 확인한 뒤 같은 화면군에 적용한다.

## 4. 색상과 표면

다음 색은 현재 토큰에서 확인한 기존 팔레트다. 새 브랜드색을 추가하지 않는다.

| 역할 | 기존 값 | 적용 |
| --- | --- | --- |
| 기본 바탕 | `#FFFFFF` | 페이지, sheet, dialog |
| 옅은 표면 | `#F7F8F9` | 흰 페이지 위 카드·입력 영역 |
| 보조 표면 | `#F3F3F3` | 비선택 chip, 중립 컨트롤 |
| 트랙 | `#E5E7EA` | 진행 바 배경, 구분이 필요한 중립 영역 |
| 브랜드 파랑 | `#5498FF` | 브랜드 강조, 선택·진행 표시 |
| 진한 파랑 | `#3E7EE0` | 기존 strong 역할, 대비 확인 후 사용 |
| 옅은 파랑 | `#EAF2FF` | 선택 보조 표면, 정보 강조 |
| 보호 파랑 | `#2B5FA8` | 기존 잠금·보호 상태 |
| 보호 표면 | `#F0F4FA` | 잠금 상태의 낮은 강도 배경 |
| 기본 글자 | `#1A1C1F` | 제목, 본문, 주요 아이콘 |
| 보조 글자 | `#71757B` | 설명·메타데이터, 배경별 대비 검수 |
| 비활성 글자 | `#D1D5DA` | disabled 전용; 필수 설명에는 사용하지 않음 |

표면은 화면 안에서 한 가지 문법을 선택한다.

- 흰 페이지에는 옅은 회색 카드와 입력을 사용한다.
- 옅은 회색 그룹 영역에는 흰 카드를 사용한다.
- 카드 안의 하위 영역은 여백·글자 위계로 구분한다. 모든 줄을 다시 카드로 감싸지 않는다.
- 파란색 배경은 선택·행동·중요 상태에 제한한다. 모든 안내 박스를 파랗게 만들지 않는다.
- 텍스트 레이어와 Auto Layout 컨테이너는 기본적으로 투명하다.
- 약한 그라데이션은 trip header 같은 넓은 장식 영역에만 허용한다.
  그라데이션이나 색상만으로 활성·선택·오류를 전달하지 않는다.

테두리는 입력 경계, checkbox, focus, 사진 위 버튼처럼 식별에 필요할 때 사용한다.
카드마다 진한 외곽선을 두지 않는다. focus는 배경과 구별되는 2px outline과
2px offset을 기본으로 하며 색 대비를 확인한다.

일반 글자는 4.5:1, 큰 글자는 3:1, 필요한 컨트롤 경계·상태 표시는 3:1을 검수 목표로 한다.
현재 밝은 파랑 위 흰색 작은 글자는 대비 통과로 간주하지 않는다.
브랜드 파랑은 선택·강조에 유지하고 filled primary CTA에는 같은 색감의 진한 파랑을 쓴다.
목표 조합은 아래 표와 semantic token에 정의한다.
보호색의 의미를 버튼색으로 재사용하는 편법은 피한다.

### 실제 대비와 채택 조합

2026-09-20 기존 HEX의 sRGB 상대 휘도로 계산했다. 아래 수치는 불투명 단색 조합이며
사진·그라데이션·opacity가 있는 합성 결과는 별도로 계산한다.

| 글자 / 바탕 | 대비 | 판정과 리뉴얼 적용 |
| --- | --- | --- |
| 흰색 / `#5498FF` | 2.87:1 | 일반·큰 글자 모두 목표 미달. 기본 버튼 조합에서 제외 |
| 흰색 / `#3E7EE0` | 3.99:1 | 일반 글자 목표 미달. 14~16px 버튼에 사용하지 않음 |
| 흰색 / `#3272D1` | 4.71:1 | filled primary CTA의 신규 목표 조합 |
| 흰색 / `#2F6ECB` | 4.98:1 | primary pressed 상태의 신규 목표 조합 |
| `#1A1C1F` / `#5498FF` | 5.95:1 | 선택 chip·브랜드 강조의 기본 조합 |
| `#71757B` / 흰색 | 4.63:1 | 흰 바탕의 보조 글자에 사용 |
| `#71757B` / `#F7F8F9` | 4.36:1 | 일반 글자 목표 미달. 카드 안 본문·메타는 기본 글자 사용 |
| `#71757B` / `#EAF2FF` | 4.11:1 | 일반 글자 목표 미달. 정보 영역 설명은 기본 글자 사용 |
| `#1A1C1F` / `#EAF2FF` | 15.16:1 | secondary·선택 보조 표면에 사용 |
| `#D1D5DA` / 흰색 | 1.47:1 | 비활성 장식 외 읽어야 하는 문구에 사용하지 않음 |

filled primary CTA는 `#3272D1` 배경과 흰 글자를 사용한다. 기존 `#5498FF`는
선택 chip·진행 표시·브랜드 강조에 진한 글자 또는 별도의 상태 표시와 함께 사용한다.
선택 chip은 check와 같은 진한 글자를 쓴다.
파란 글자를 링크의 유일한 식별 방식으로 쓰지 않는다. 기본 글자색과 underline을
기본 링크 표현으로 사용하며 상태·배경이 바뀌어도 대비를 다시 확인한다.
얇고 옅은 경계선은 장식용이다. 조작 경계가 꼭 필요한 입력·checkbox에는
3:1을 만족하는 별도 경계 역할을 사용한다.

### 의미별 목표 토큰

아래 이름은 리뉴얼용 설계 alias이며 실제 코드 export 이름이 아니다.
기존 생성물과 충돌하면 Figma 변수와 생성 파이프라인에서 매핑한다.

| 설계 alias | 값 또는 연결 | 기존 토큰과 관계 |
| --- | --- | --- |
| `surface.canvas` | `#FFFFFF` | `color/bg/default` 유지 |
| `surface.group` | `#F7F8F9` | `color/bg/subtle` 유지 |
| `surface.control` | `#F3F3F3` | 기존 primitive의 semantic alias 추가 후보 |
| `surface.selected` | `#EAF2FF` | `color/action/subtle` 유지 |
| `text.default` | `#1A1C1F` | `color/text/primary` 유지 |
| `text.secondaryOnWhite` | `#71757B` | 흰 바탕에서 기존 secondary 사용 |
| `text.onTint` | `#1A1C1F` | tint 위 설명·본문 역할 추가 후보 |
| `brand.accent` | `#5498FF` | 기존 `color/action/primary`; 브랜드·선택 강조로 역할 조정 후보 |
| `action.primary.bg` | `#3272D1` | 접근 가능한 신규 semantic token 후보 |
| `action.primary.pressed` | `#2F6ECB` | 신규 semantic token 후보 |
| `action.primary.fg` | `#FFFFFF` | 기존 `color/action/onPrimary` 유지 |
| `action.secondary.bg / fg` | `#EAF2FF / #1A1C1F` | 기존 palette의 새 조합 |
| `action.disabled.bg / fg` | `#E5E7EA / #1A1C1F` | `준비 중`·disabled 상태와 함께 표시 |
| `border.control` | `#71757B` | 필요한 control 경계에만 사용 |
| `focus.ring` | `#1A1C1F` | 밝은 표면 기준; 어두운 사진 위는 흰 배경 받침과 함께 검수 |

success·warning·error를 위해 새 무지개색 팔레트를 도입하지 않는다. 현재 버전은
기본 글자, 구별되는 상태 아이콘, 명확한 제목과 필요한 행동으로 전달한다.
삭제 같은 파괴적 행동은 구체적인 label과 기존 확인 절차로 구분한다.

### 토큰 계층과 변경 관리

색·크기 원시 값 → 사용 목적 → 컴포넌트 역할 순으로 연결한다.
아래는 목표 매핑 예시이며 기존 export 이름을 일괄 변경하는 지시가 아니다.

| 계층 | 목표 예시 | 관리 원칙 |
| --- | --- | --- |
| Primitive | `blue.action = #3272D1`, `space.4 = 16px` | 실제 값은 한 곳에서 정의 |
| Semantic | `action.primary.bg → blue.action` | 사용 목적과 허용 배경을 명시 |
| Component | `button.primary.bg → action.primary.bg` | 같은 역할은 공통 alias 재사용 |
| Component | `chip.selected.fg → text.default` | 선택과 잠금 등 도메인 의미를 섞지 않음 |

alias는 순환 참조·없는 참조 없이 최종 값으로 해석되어야 한다. 컴포넌트마다 같은
색의 새 토큰을 만들지 않는다. 독립적으로 바꿀 필요가 있을 때만 component alias를 추가한다.
폰트는 family·weight·size·line-height를 함께 관리하고 숫자에는 단위를 기록한다.

변경 기록에는 `이전 이름/값 → 새 이름/값 / 이유 / 영향받는 component·node /
적용 상태 / 검수 증거 / 복구 기준`을 남긴다. 상태는 제안 → Figma 검수 → export →
구현 검수로 구분한다. 이름 삭제·의미 변경은 major, 호환 역할 추가는 minor,
의미를 유지하는 명세 수정은 patch로 관리하되 이 문서 버전과 토큰 배포 버전을 혼동하지 않는다.
기존 토큰은 소비 instance·코드의 전환 확인 전 삭제하지 않는다.

### 높이감 규격

| 역할 | 목표 효과 | 사용처 |
| --- | --- | --- |
| `elevation.flat` | shadow 없음 | 기본 카드, 목록, 본문 |
| `elevation.raised` | `0 2px 8px rgb(26 28 31 / 8%)` | 콘텐츠 위 검색·떠 있는 메뉴 |
| `elevation.overlay` | `0 8px 32px rgb(26 28 31 / 12%)` | dialog·sheet, scrim과 함께 |
| `scrim.modal` | `#1A1C1F`, opacity 40% | modal 배경; 화면 본문 전체 opacity를 낮추지 않음 |
| `gradient.header` | `#EAF2FF → #FFFFFF`, 세로 | 선택적 trip header 장식, 기본은 단색 |

그림자를 모든 카드에 적용하지 않는다. 모서리·표면·간격으로 구분하고 overlay에 깊이를 준다.
겹침 순서는 콘텐츠 → sticky chrome → popover → modal scrim → sheet/dialog →
해당 modal 내부 피드백이다. 배경 toast가 modal 위로 뜨거나 modal의 닫기를 가리면 안 된다.
이 순서는 stack 규약이며 임의의 큰 z-index를 화면마다 추가하는 기준이 아니다.

## 5. 타이포그래피

기준 폰트는 Pretendard다. 현재 코드가 사용하는 400·500·700 굵기를 우선 사용한다.
아래 표는 리뉴얼 목표 규격이며 기존 생성 토큰을 변경했다는 뜻이 아니다.

| 역할 | 크기 / 행간 | 굵기 | 용도 |
| --- | --- | --- | --- |
| 화면 제목 | 24 / 34px | 700 | 핵심 페이지 제목 |
| NavBar·섹션 제목 | 20 / 28px | 700 | 내비게이션, 주요 섹션 |
| 카드 제목 | 17 / 24px | 500 또는 700 | 장소·게시물 제목 |
| 본문·입력 | 16 / 24px | 400 | 설명, 실제 입력값 |
| 기본 버튼 | 16 / 24px | 500 | 주요 CTA |
| 보조 행동·chip | 14 / 20px | 500 | 필터, 보조 버튼 |
| 메타데이터 | 13 / 20px | 400 | 날짜·출처·보조 정보 |
| 짧은 보조 표시 | 12 / 18px | 500 | 비핵심 배지; 설명 본문에는 사용하지 않음 |

출처·실패 사유·개인정보 안내를 10~11px로 줄여 맞추지 않는다.
긴 본문과 다국어 문구는 높이가 늘어나게 한다. 제목은 필요하면 2줄 이상 허용한다.
목록에서 줄임이 필요한 제목은 상세에서 전문을 제공하고, 오류·권리·출처 문구는 자르지 않는다.
영어도 같은 폰트 체계를 사용하고 한국어 자간을 영어에 강제로 적용하지 않는다.

Figma에서 Pretendard가 사용 불가하면 Noto Sans KR 대체 상태를 작업 주석에 기록한다.
대체 폰트의 화면을 Pretendard 검수 완료로 보고하지 않는다. 실제 구현 폰트로
줄바꿈과 한글 glyph 표시를 확인한 후 완료 판정한다.

## 6. 크기·간격·레이아웃

| 항목 | 리뉴얼 기준 |
| --- | --- |
| 기본 디자인 프레임 | 393×852px; 852px는 viewport이며 콘텐츠 최대 높이가 아님 |
| 좁은 화면 검수 | 360px, 그리고 200% 확대 시 실제 줄어든 콘텐츠 폭 |
| 좌우 여백 | 16px; 393px에서 기본 콘텐츠 폭 361px |
| 간격 척도 | 기존 4·8·12·16·20·24·28·32·48px |
| 관련 요소 간격 | 아이콘-문구 8px, 제목-설명 4~8px |
| 카드 사이 | 12~16px |
| 카드 내부 | 16px; 큰 안내 영역은 20~24px |
| 섹션 사이 | 24~32px |
| NavBar | 기본 56px + safe area; 긴 제목은 영역 확장 |
| 버튼·입력 | 기본 최소 높이 48px; 주요 하단 CTA 최소 52px |
| 보조 행동·chip | 최소 터치 높이 44px |
| 아이콘 | 일반 20~24px, 텍스트 옆 보조 16~20px |

모서리 16·20·24px 등은 신규 목표 토큰이다. 기존 radius 토큰과 별도로
Figma에서 정의·검수한 뒤 정식 추출한다. 화면마다 임의 숫자로 도입하지 않는다.

한 화면은 세로 흐름을 기본으로 하고 긴 콘텐츠는 세로 스크롤한다.
고정 하단 CTA는 safe area와 콘텐츠 하단 여백을 포함하며 마지막 항목을 가리지 않는다.
toast는 하단 CTA·탭바 위에 배치하고 여러 개를 겹치지 않는다.
키보드가 열리면 입력과 오류가 보이도록 스크롤하고 CTA가 편집 영역을 덮지 않게 한다.

NULLNULL은 모바일 우선 React PWA다. 네이티브 앱처럼 명료한 계층과 터치 크기를 사용하되,
브라우저 history·주소 표시줄·visual viewport·키보드·focus·반응형 reflow를 보존한다.
네이티브 전용 제스처, haptic, OS control을 실제 지원 여부 없이 화면 동작으로 약속하지 않는다.

넓은 화면에서는 현재 shell 구조 안에서 콘텐츠 폭과 여백을 조정한다.
Airbnb의 데스크톱 예약 패널·햄버거 메뉴를 새 정보 구조로 도입하지 않는다.

### 앱 shell과 반응형 규약

| 가용 콘텐츠 폭·상황 | 동작 |
| --- | --- |
| 360~430px | 단일 열, 좌우 16px, 피드·일정 콘텐츠 폭 Fill |
| 360px 미만 또는 200% 확대 | 16px gutter를 기본으로 유지, chip·행동 세로 재배치, 고정 min-width 없음 |
| 431~767px | 동일한 정보 구조, 긴 읽기·폼은 최대 560px 중앙 정렬을 리뉴얼 목표로 사용 |
| 768px 이상 | 폼 560px·일정 720px·탐색 960px 이하 목표; 탐색 카드만 충분한 폭에서 2열 |
| 모바일 키보드 표시 | visual viewport에 맞춰 입력 노출, 하단 CTA는 가용 높이 부족 시 콘텐츠 흐름으로 전환 |
| 긴 콘텐츠·확대 | 일반 화면은 main 하나가 스크롤; modal은 자기 본문이 스크롤 |

위 최대 폭은 새 레이아웃 목표이며 기존 앱 shell에 적용한 값은 아니다.
2열은 카드 하나가 최소 280px를 확보할 때만 사용하고, 모바일 전용 기능이나 메뉴를 추가하지 않는다.
safe area는 shell 또는 overlay가 한 번만 소유한다. 페이지와 NavBar에서 중복으로 더하지 않는다.
Figma의 상태바·notch는 기기 preview 장식이며 웹/PWA DOM에 다시 그리지 않는다.

탭바는 기존 P0 4개 목적지를 유지하고 승인된 P1 구성에서 검색 진입을 연결한다.
아이콘 24px, 라벨 12/18px, 각 항목 최소 44×44px, 기본 bar 최소 64px + bottom safe area다.
선택은 아이콘/텍스트 형태와 상태를 함께 표시한다. 긴 영어 라벨은 2줄과 bar 높이 증가를 허용한다.
확대 상태에서 항목이 들어가지 않으면 단위 항목을 줄바꿈하고 같은 목적지·순서를 유지한다.
하단 CTA와 탭바가 공존하면 CTA는 탭바 위에 놓고 main의 마지막 항목까지 접근할 수 있어야 한다.

### 목표 숫자 토큰 요약

| 그룹 | 목표 토큰 |
| --- | --- |
| radius | `control:12`, `card:16`, `feature:20`, `overlay:24`, `pill:999` |
| control | `touchMin:44`, `defaultMin:48`, `primaryMin:52`, `navMin:56`, `tabMin:64` |
| padding | `screen:16`, `card:16`, `fieldInline:16`, `buttonInline:16`, `chipInline:16`, `overlayTop:24` |
| gap | `iconLabel:8`, `stack:8`, `cardList:12`, `section:24`, `majorSection:32` |
| icon | `inline:16`, `action:20`, `navigation:24` |

단위는 px 기준 설계값이다. 구현 글자·연관 간격은 확대에 대응하며, 최소 높이는 고정 높이가 아니다.
기존 spacing 토큰은 재사용하고 radius·control 등 없는 역할만 변수로 보완한다.
카드·폼·행의 좌우 기준선은 16px로 통일하고, 구성 요소 사이는 12px, 아이콘·라벨과 작은 요소
사이는 8px을 사용한다. `IconButton`의 0px은 44px hit area 안에서 glyph를 중앙 정렬하는 값이고,
`NavBar`·`Sheet`의 0px은 자식 슬롯이 16px inset을 소유하는 shell 예외다. 예외는 중복 padding을
막기 위한 소유권 차이일 뿐 화면의 시각 기준선을 바꾸지 않는다.

### 화면 템플릿

화면마다 header·본문·CTA를 새로 배치하지 않는다. 다음 다섯 골격에서 시작하고,
필요한 기능만 조합한다. 상태바는 Figma 기기 preview에만 포함한다.

| 템플릿 | 위에서 아래 순서 | 적용 화면과 규칙 |
| --- | --- | --- |
| 탐색·목록 | NavBar → 검색/segment → 필터·상태 요약 → 결과 목록 → pagination → TabBar | 피드·검색·Live·알림. 필터 변화 중에는 기존 결과와 갱신 상태를 함께 표시 |
| 상세·읽기 | NavBar → hero optional → 제목·핵심 상태 → 본문 섹션 → 관련 장소·출처 → 행동 | 게시물·장소·데이터 안내. hero가 없어도 제목 baseline과 여백 유지 |
| Wizard·폼 | NavBar → progress → 질문·설명 → 입력/선택 → validation → Bottom CTA | 여행 만들기·게시물 작성·로그인. 입력은 스크롤하고 CTA가 오류를 가리지 않음 |
| 일정·편집 | Trip header → day/segment → 상태 안내 → TripItem 목록 → 보조 추가 행동 → 저장 CTA | 내 여행·최적화. header와 일정 카드의 정보 순서를 모든 variant에서 유지 |
| 결과·복구 | NavBar → 상태 제목·설명 → 유지된 데이터/결과 → primary 복구 → secondary 이동 | empty·error·offline·success·stale. 사용자가 잃지 않은 내용을 먼저 보여줌 |

템플릿의 progress·저장 CTA·TabBar·pagination은 해당 화면에 실제 기능이 있을 때만 둔다.
단일 로그인 폼에 wizard 단계를 추가하거나 즉시 저장되는 행동에 새 저장 단계를 만들지 않는다.
보기 모드의 일정에는 편집 완료 CTA를 강제로 넣지 않는다.

sheet와 dialog는 위 템플릿 위에 올라가는 overlay다. 기존 화면이 다른 순서를 사용해도
기능상 이유가 없다면 이 골격에 맞춰 통일한다. 한 화면의 동일한 primary 행동을
본문 카드와 고정 하단 CTA에 동시에 반복하지 않는다.

### 리뉴얼 금지 패턴

- 흰색 페이지·흰색 카드·흰색 버튼을 경계 없이 겹쳐 조작 영역을 숨기지 않는다.
- 모든 묶음에 테두리를 두거나 카드 안에 같은 모양의 카드를 반복하지 않는다.
- 모든 안내 영역을 옅은 파랑으로 채워 선택·정보·성공의 위계를 같게 만들지 않는다.
- 제목·설명마다 별도의 흰색 text background를 넣지 않는다.
- 긴 문구를 맞추려고 글자를 축소하거나 고정 폭 chip·고정 높이 카드로 자르지 않는다.
- 버튼 안의 plus·close·menu를 글자나 이모지로 만들거나 label보다 크게 두지 않는다.
- 기능이 없는 빈 icon slot, 삭제된 버튼 자리, 투명한 hit area를 남기지 않는다.
- 동일 primary CTA를 화면 안에서 반복하거나 서로 다른 행동을 같은 강조도로 두지 않는다.
- `disabled`와 `selected`, `loading`과 `success`, 후보 저장과 일정 추가를 같은 모양으로 합치지 않는다.
- 지도·그라데이션·그림자·blur를 콘텐츠 부족을 채우는 장식으로 사용하지 않는다.
- 계약·컴포넌트 재사용을 확인하지 않고 Airbnb의 예약·평점·숙소 패턴을 추가하지 않는다.

## 7. 공통 컴포넌트 규칙

### 버튼과 아이콘

- primary는 현재 작업의 가장 중요한 행동에 사용한다. 같은 행동을 본문과 하단에 중복하지 않는다.
- secondary는 중립 또는 옅은 표면과 진한 글자, tertiary는 투명 배경을 사용한다.
- disabled는 활성 secondary와 구별하고 필요한 이유를 옆에 읽을 수 있는 글자로 표시한다.
- loading은 같은 버튼 폭을 유지하고 `저장 중` 같은 문구와 중복 제출 제한을 함께 둔다.
- 아이콘은 기존 벡터 세트를 사용한다. 문자 `+`, `×`, 이모지를 아이콘 대신 조합하지 않는다.
- `장소 추가`의 plus는 16~20px, 문구는 14~16px로 두고 중앙 정렬한다.
- 아이콘 버튼은 44×44px 이상의 독립된 hit area와 접근성 이름을 갖는다.
- hover는 약한 표면 변화, pressed는 짧은 색 변화, focus는 명확한 outline으로 구분한다.

### Chip과 선택 컨트롤

폭은 `텍스트 실제 너비 + 좌우 12~16px + 아이콘과 간격`으로 계산한다.
고정 56px·72px 폭에 모든 문구를 넣지 않는다. 최대 폭은 부모의 가용 폭이다.
Auto Layout은 Hug contents를 기본으로 하고 chip 목록에는 wrap과 8px 간격을 적용한다.
긴 chip 하나가 가용 폭을 넘으면 문구가 줄바꿈되고 높이가 늘어난다.
선택 의미가 사라지는 말줄임·clip·글자 축소는 금지한다.

선택 상태는 색과 함께 check 또는 명시적인 상태를 제공한다.
적용 필터의 해제는 키보드와 터치로 수행할 수 있어야 하며 삭제 동작 영역도 44px를 확보한다.
선택 chip은 전체를 한 조작으로 사용한다. 해제만 가능한 적용 필터는 chip 전체가 해제 버튼이고,
닫기 아이콘은 그 행동의 표시다. chip 본문에 별도 행동이 실제로 필요하면 본문과 해제를
각각 독립된 44px 영역으로 나누며 button 안에 button을 중첩하지 않는다.
check의 출현으로 줄바꿈이 흔들리지 않게 하는 예약 공간은 선택 chip에만 허용한다.
카드에서 삭제된 행동의 빈 슬롯을 남기는 것과 구분한다.
관심사·동행·여행 스타일은 같은 규칙을 공유한다.
날짜 탭 역시 360px·확대 상태에서 wrap 또는 줄바꿈 가능한 구성으로 전환한다.

### 입력과 검색

라벨을 입력 바깥에 유지하고 필수·선택을 명시한다. placeholder만으로 용도를 설명하지 않는다.
본문 textarea는 상단 정렬한다. 입력이 여러 줄이면 높이가 늘어난다.
오류는 해당 필드 아래 텍스트와 오류 상태로 표시하고 사용자가 입력한 값을 유지한다.
입력 도중 매 글자마다 오류를 띄우지 않는다. 제출 시 오류 필드와 설명을 연결하고
첫 오류로 이동할 수 있게 한다. 이미 표시된 오류는 수정 과정에서 갱신한다.
미디어 업로드 전에는 계약에 있는 형식·개수·용량 제한을 안내하고 수치를 임의로 만들지 않는다.
검색의 지우기·취소 동작을 구분하며 44px 영역을 확보한다.
입력과 버튼이 같은 흰색일 때는 표면 차이나 필요한 경계선으로 식별한다.

### 카드

카드는 정보 묶음이며 카드 전체와 내부 버튼의 클릭 영역을 중첩하지 않는다.
제목·메타데이터·행동은 명시적인 행으로 나눈다. 숨긴 아이콘의 빈 슬롯을 남기지 않는다.
이미지가 없는 카드는 별도의 텍스트 중심 variant를 사용한다.
이미지 로딩 실패에 의미 없는 회색 사각형을 영구적으로 남기지 않는다.

### Sheet와 dialog

선택·필터·보조 편집에는 sheet, 변경 폐기·해제 확인에는 dialog를 사용한다.
제목, 닫기, 본문, 하단 행동 순서를 통일한다. scrim은 내용과 배경이 확실히 분리되도록 검수한다.
긴 sheet 본문은 독립적으로 세로 스크롤하고 고정 행동 영역과 겹치지 않는다.
열릴 때 focus 진입, 배경 inert, 닫힌 뒤 원래 조작으로 focus 복귀를 설계 주석에 남긴다.
닫기나 뒤로가기의 의미는 현재 기능 계약을 따른다.

### 핵심 조합의 고정 규칙

**FeedPost:** 기본 이미지 비율 4:3, 텍스트 간격 8px, 카드 내부 16px.
장소 설명 영역은 Fill, 담기 영역은 Hug/min 44px이다. 버튼을 설명 위에 absolute로 얹지 않는다.
좁은 폭에서는 담기를 별도 하단 행으로 보낸다. 게시물 보관은 별도 버튼으로 남는다.

**TripItem:** 보기 상태는 제목과 시각, 편집 상태는 독립된 편집 행을 가진다.
모든 아이콘을 장소명과 한 줄에 몰지 않는다. 설명·출처는 전문 wrap하고 카드 높이는 Hug다.
compact는 메타 순서와 여백만 조정하며 글자 크기·44px 조작 영역을 축소하지 않는다.
Default·Changed·Unavailable의 카드 배경은 모두 `surface/group`을 사용한다. 상태 안내가 필요하면
`surface/control` 안에 이유 문구를 가로·세로 중앙 정렬하고, 선택·복구 행동에만 `blue/action`을 사용한다.
날짜 고정·시간 고정은 각각 44px 이상의 동일 폭 제어를 사용하며, 8px 간격의 아이콘과 라벨
묶음을 제어의 가로·세로 중앙에 정렬한다.

**StateNotice:** Loading·Empty·Error·Offline·Success의 카드 배경과 아이콘 컨테이너는 각각
`surface/group`과 `surface/control`로 통일한다. 아이콘 모양과 제목·설명이 상태 의미를 담당하고,
아이콘·CTA는 공통 `blue/action`을 사용한다. 오류·오프라인·성공을 서로 다른 파스텔 카드 배경으로
구분하지 않는다.

**PostPhotoPreview·PostPhotoField:** 게시 사진 1장만 지원한다. 기존 MediaTile·MediaPicker를
313×235px의 큰 4:3 미리보기와 명시적인 선택·교체·재시도 버튼으로 변경한다.
사진 프레임을 먼저 배치하고 행동 버튼은 프레임 아래 313×52px 전체 폭으로 둔다.
순서 배지·다중 선택·3열 목록은 없다.
OS 선택창은 `input type="file" accept="image/*"` 하나로 연다. `capture`, `multiple`,
`getUserMedia` 및 카메라 강제 UI는 사용하지 않는다. 미리보기 crop은 원본 편집을 의미하지 않는다.
진행률은 측정 가능한 전송 값만 사용하고, 이미지 검증 중에는 불확정 진행 안내를 표시한다.
형식 위장·이미지 아님은 다시 선택, 크기 초과는 확정 계약의 상한 문구와 다시 선택,
만료는 새 업로드 요청과 재전송을 제공한다. 크기·TTL·지원 형식의 미확정 수치는 만들지 않는다.
실패·취소·교체 시 캡션·해시태그·선택 장소를 보존하며 업로드 완료를 공개 완료로 표현하지 않는다.

**PostCaptionField·PlaceAttachment:** 별도 제목 필드는 사용하지 않는다. 캡션은 최대 20,000자이며
본문형 FormField를 재사용해 상단 정렬한다. 해시태그는 별도 입력란이 아니라 캡션 안에서 작성한다.
필수 여부와 파싱 규칙은 확정 계약을 따르며 길이 초과는 필드 아래 표시한다. 장소는 기존 PlaceSummary 검색을
재사용해 최대 50곳을 명시적으로 선택한다. 개별 해제·선택 개수·전체 관리 진입을 제공하며
50곳에서는 추가만 막고 관리·해제는 유지한다. 긴 선택 목록은 스크롤 가능한 sheet에서 관리하고
작성 영역에는 요약을 표시한다. 검색 실패에도 기존 선택과 작성 값은 보존한다.

**PostPublishBar:** 사진 업로드 미완료 시 게시를 disabled로 표시하고 이유를
제공한다. 버튼 근처 권리 안내는 `게시하면 본인이 촬영·제작한 사진이며 공개에 동의하는 것으로 봅니다.`로
표시하며 체크박스나 별도 동의 상태는 없다. 익명 session으로 작성할 수 있다.
게시 중에는 중복 제출을 막고 사진 확인에 시간이 걸릴 수 있음을 안내한다.
`createPost`의 201 응답에서 PUBLISHED와 coverUrl이 확인된 뒤 `게시물이 공개됐어요`를 표시한다.
post PENDING/PROCESSING·폴링·검토 대기·승인 예정·운영자 거절 화면은 없다.

**NotificationRow:** 개별 알림마다 큰 radius·그림자·아이콘 배경을 반복하지 않는다. 현재 한국어는
105px 행을 기본으로 하며 왼쪽 아이콘 없이 좌우 16px, 279px 콘텐츠, 24px chevron을 사용한다.
chevron은 행 전체 높이 중앙에 정렬한다. 행 사이는 콘텐츠 시작점부터 약한 divider로 구분한다. 안 읽음은 옅은 파랑 표면과
`방금 · 새 알림` 전문을 함께 쓰고 pill badge를 반복하지 않는다. 전체 행이 하나의 터치 대상이므로
chevron에 별도의 44px 버튼 영역을 만들지 않는다. 긴 영어·확대에서는 본문과 행 높이가 함께 늘어난다.

**Date picker:** 360px에서는 16px gutter 안 328px에 7열을 배치해 날짜 hit area를
최소 44px로 확보한다. 내부 padding·열 간격을 더해 44px 미만으로 만들지 않는다.
확대 후 이 폭을 확보할 수 없으면 같은 날짜 선택을 제공하는 접근 가능한 세로 선택 방식으로
전환한다. 새 데이터 필드·기간 규칙은 추가하지 않는다. 전환 상태도 별도 디자인 검수 대상이다.

**Sheet/Dialog:** 모달 밖을 누르거나 swipe하는 행동은 기존 닫기 정책을 따른다.
저장되지 않은 입력이 있으면 기존 이탈 확인을 거친다. Escape·뒤로가기·닫기 버튼의
결과를 동일하게 정의하고 요청 취소 기능이 없는 처리에 `취소`를 붙이지 않는다.

피드 카드 하단에는 관련 장소 정보와 `담기` 행동을 서로 밀어내지 않는 행으로 둔다.
긴 제목과 설명은 위에서 높이를 차지하고 버튼은 독립된 정렬 기준을 갖는다.
게시물 보관 버튼을 후보 담기로 합치거나, 담기를 일정 확정처럼 표현하지 않는다.

일정 카드 header는 `이동 핸들 / 장소 제목 / 시각 / 메뉴 / 삭제`의 역할을 분리한다.
393px에서 한 줄이 복잡하면 제목·시각과 편집 행동을 두 행으로 나눈다.
장소 설명, 혼잡도, 출처, 잠금은 아래에 동일한 순서로 둔다.
날짜·시간·필수 방문·예약 잠금은 독립 상태로 유지한다.
추가 완료는 배지나 짧은 표면 강조로 알리고 카드 높이·제목 정렬·기능은 같은 variant 규칙을 따른다.

`담아둔 장소`는 후보 목록 진입으로, `장소 추가`는 직접 검색 진입으로 구분한다.
둘을 거대한 동급 primary 버튼으로 만들지 않는다. 보조 버튼의 폭은 내용에 맞추고
44px 터치 높이를 유지한다.

## 9. P1 전체 디자인 범위

P1을 포함해 디자인하되 enabled 화면과 capability OFF 화면을 함께 관리한다.
화면 존재가 기능 배포·계약 승인을 의미하지 않는다. 아래 목록은 기능 누락 방지용이며
정확한 입력 항목과 동작은 연결된 실행 계획·계약을 따른다.

| 범위 / 추적 | 반드시 설계할 상태 |
| --- | --- |
| 통합 검색 / `FE-P1-103` | 기본·최근 검색, 초기/배경 loading, 결과·pagination, empty, 오류·offline, filter OFF, 필터 draft/apply/reset/close, 비교 불가 |
| 게시물 작성 / `FE-P1-104`, #312 | 게시 사진 1장·캡션과 해시태그·연결 장소 검색/선택·최대 50곳, 권리 안내 문구, 업로드·형식 오류·크기 초과·취소·만료, 게시 중·즉시 공개 완료, 이탈·오류·offline; 별도 제목과 운영자 검토 상태는 사용하지 않음 |

| 주변 추천·재계획 / `FE-P1-102` | 동의 전·동의·거부·철회, 목록·empty·실패, preview·비교 불가·OFF |
| AI 초안·DAY / `FE-P1-105` | 생성 중·초안·근거·확인, DAY 전후 비교, 실패·unavailable·OFF, 승인 전 일정 유지 |
| 정식 로그인 / `FE-P1-106` | 기존 로그인 node를 아이디·비밀번호 방식으로 확장, 기본·입력·처리 중·인증 실패·일반 오류·복구, 익명 데이터 승계 preview·confirm·충돌, OFF |

| 전체 여행·경로 확장 / 제품 P1 | TRIP 범위와 route provider 의존 상태 검토, 경로 없음·비교 불가, preview·승인 경계; 승인 범위 확인 후 상세화 |
| 영어 장소 정보 / 제품 P1 | 긴 이름·설명, 제공 언어·정보 부재, 번역 검수; 없는 영문 정보를 디자인에서 생성하지 않음 |

검색 결과의 장소/게시물 범위는 아직 미확정이다. 결과 컴포넌트는 유형을 나눌 수 있게
설계하되 두 유형이 지원된다는 확정 문구나 활성 탭은 승인 전 샘플 주석으로 구분한다.
필터명·정렬 조건·최근 검색 저장 위치와 기간도 확정값처럼 쓰지 않는다.
개별 삭제·전체 삭제와 고지 영역은 확보하고 검색어를 주소 형태로 표시하지 않는다.
필터 draft와 현재 적용값은 실제 선택 표시와 문구가 일치해야 한다.

게시물은 사용자가 게시를 실행하고 업로드·생성이 성공하면 피드에 즉시 공개한다. 운영자 검토
대기·승인·거절 화면을 노출하지 않는다. 업로드 완료와 공개 완료는 처리 중에는 구분하되,
성공 화면은 공개 완료만 알린다. 게시 사진은 1개이며,
실패·오프라인에서도 사진 미리보기·캡션·해시태그·선택 장소를 유지한다. 임시 작성이라는 이유로
자동 저장을 약속하지 않는다. 파일 형식·크기·안전성의 동기 검증은 별도 기술 정책이며,
운영자 수동 승인처럼 표현하지 않는다.

정식 로그인은 중요 P1 흐름으로 전체 상태를 설계한다. 승인된 인증 방식과
익명 데이터 승계 확인을 따른다. 디자인 장식을 위해 소셜 로그인 사업자를 추가하지 않는다.
제출 profile에서는 기존 로그인 준비 중·익명 핵심 흐름을 보존한다.

현재 검색·게시물 작업물은 각각 `889:5420`, `889:5421` section이다.
이전 명명에서 검색에 S12를 사용했으나 실행 계획의 S12는 알림이므로,
핸드오프는 화면 번호만으로 매칭하지 않고 기능 ID·route·node ID를 함께 사용한다.
알림·주변 추천·AI 초안·DAY·로그인은 기존 node의 상태 확장을 우선한다.

## 10. 데이터와 문구

혼잡도는 숫자·단계 문구와 시각 표시를 함께 쓴다. 관측·예측·REPLAY·오래된 정보·
데이터 부재를 구분하며 REPLAY에는 실시간이 아님을 명시한다.
출처와 기준 시점은 해당 값 가까이에 둔다. 상세 설명으로 이동하더라도 핵심 상태를 숨기지 않는다.
비교 불가를 0·보통·개선 없음으로 바꾸거나 서로 다른 출처를 하나의 순위로 합치지 않는다.
대안이 없는 상태와 통신 실패도 구분한다.

제품 화면에는 사용자가 다음 행동을 결정하는 데 필요한 문장을 쓴다.
`계약 확정 후 교체`, `서버 필드`, `capability`, `요청 0건` 같은 설계 메모는
화면 바깥 annotation으로 옮긴다. 미확정 문구는 주석에서 표시하고 실제 제품 문구와 분리한다.
`서울 산책을 소개해요` 같은 예시는 샘플임을 주석에 명시한다.

| 상태 | 표시 원칙 |
| --- | --- |
| 초기 loading | 실제 결과와 구별되는 skeleton 또는 로딩 문구 |
| 배경 loading | 기존 콘텐츠 유지와 갱신 중 표시 |
| empty | 데이터 없음의 이유와 지원되는 다음 행동 |
| error | 실패한 범위, 유지된 입력·일정, 재시도 또는 복구 |
| disabled/OFF | 준비 중 또는 사용 불가 이유; 가짜 활성 CTA 금지 |
| success | 완료된 실제 행동과 다음 이동; 잠깐의 toast만으로 핵심 결과를 전달하지 않음 |
| submitting | 중복 제출 차단, 처리 중 텍스트, 실제 지원되는 이탈 동작 |
| conflict/stale | 최신 정보 확인·재계산 등 기존 복구 흐름 |

## 11. 반응형·접근성·모션

- 393px 기본, 360px, 200% 확대에서 검수한다. 화면 전체 축소로 통과시키지 않는다.
- 가로 스크롤·고정 최소 폭 없이 reflow한다. chip·행동은 wrap하고 좁으면 세로로 쌓는다.
- 높이는 텍스트에 따라 증가한다. 날짜나 긴 영어 단어 때문에 부모 폭이 늘어나지 않게 한다.
- 한국어와 영어 긴 문구, 긴 장소명, 긴 오류·출처, 큰 글자 설정을 대표 상태에 넣는다.
- 모든 조작의 hit area 최소 44×44px를 유지하고 인접 영역이 겹치지 않게 한다.
- focus 순서와 시각 순서가 일치해야 한다. 선택·읽음·잠금은 색 외 표시와 접근성 상태를 갖는다.
- 드래그로만 가능한 조작을 만들지 않는다. 기존 키보드·버튼 대안을 유지한다.
- 대조·스크린샷 확인은 구조적 접근성 검사를 대체하지 않는다.
- 움직임은 상태 전환을 이해하는 데 필요한 정도로 쓴다. 단순 반응은 120~180ms,
  sheet 전환은 200~260ms를 목표로 검수하고 reduced motion에서는 이동 효과를 줄인다.
- 업로드 취소와 화면 이동처럼 서로 다른 동작을 애니메이션만으로 같은 의미로 표현하지 않는다.

### 상태 알림과 모션 세부값

| 상황 | 규칙 |
| --- | --- |
| 버튼 반응 | 120ms 색 변화, 기본적으로 위치·크기 변화 없음 |
| chip 선택 | 150ms 배경·check 전환, 주변 chip이 밀리지 않도록 아이콘 공간 고려 |
| sheet·dialog | 220ms 진입, 180ms 퇴장, `cubic-bezier(0.2, 0, 0, 1)` 목표 |
| reduced motion | 이동·scale·shimmer 제거, 필수 진행 상태는 정적 문구로 유지 |
| background loading | 현재 목록 유지, 로딩 알림을 반복 읽지 않고 시작·결과를 필요한 수준으로 전달 |
| 오류·완료 알림 | 화면의 제목/관련 필드/상태 영역과 연결, 초점 강탈·반복 알림 방지 |
| toast | 기본 5초는 단순 보조 피드백에만 적용; 읽는 중·focus 시 사라지지 않음 |
| 되돌리기·중요 오류 | toast 만료와 무관하게 지속적인 결과·복구 영역을 제공 |

모션 값은 새 리뉴얼 목표다. 실제 동작의 서버 처리시간, 취소 가능 여부,
되돌리기 기한을 애니메이션 시간으로 대체하지 않는다.

## 12. Figma 제작과 구현 인계

1. 현재 화면별 기능·control·상태 목록을 기록한다. 제거된 듯 보이는 항목은 계약과 대조한다.
2. 사용자 수정이 있는 기준 프레임의 node와 시점을 기록하고 원본을 보존한다.
3. 기존 NavBar, Bottom CTA, card, chip, sheet, dialog, 상태 컴포넌트의 구조를 우선 사용한다.
4. 새 variant가 필요하면 같은 역할의 master를 확장한다. 화면별 detached 복사본을 늘리지 않는다.
5. 새 master의 검수 전 변경이 기존 MVP 전체로 퍼지지 않도록 적용 대상을 관리한다.
6. 본문·카드·chip은 Auto Layout, Fill/Hug와 wrap을 지정한다. 좌표 고정은 overlay·장식에 제한한다.
7. 색·간격·글자·radius를 변수와 스타일에 연결한다. raw 값은 토큰 후보로 명시한다.
8. 기능 ID → 이전/새 node·state → 기존 operation/schema → 검수 근거를 연결한다.
9. 컴포넌트 검수 후 화면군에 전파하고 한국어·영어·좁은 폭·확대 상태를 재검수한다.
10. 승인된 시각 토큰은 Figma에서 추출하고 `tokens:build`, `tokens:check`를 따른다.

이 문서의 목표 수치를 근거로 `tokens.json`이나 생성 `tokens.css`를 수기 수정하지 않는다.
디자인 변화와 실제 적용 상태를 나눠 기록하고, 미확정 P1 계약을 디자인 완료로 해제하지 않는다.

## 13. 리뉴얼 완료 판정

- [ ] 기존 기능과 P1 항목이 화면·상태 목록에 모두 연결돼 있다.
- [ ] 계약·상태 전이·저장 의미가 보존되고 지원되지 않는 기능이 활성화되지 않았다.
- [ ] 사용자 기준 Trip header와 같은 화면군의 정렬·간격·padding이 일치한다.
- [ ] 카드의 버튼, 제목, 시간, 메뉴가 충돌하지 않고 숨긴 요소의 빈 슬롯이 없다.
- [ ] chip 문구와 선택 표시가 잘리지 않으며 긴 문구에서 wrap한다.
- [ ] 글자 배경의 흰 사각형, 과도한 plus, 문자 아이콘이 없다.
- [ ] 밝은 배경 위 버튼·입력·카드가 구별되고 실제 색 대비가 검증됐다.
- [ ] 일반·loading·empty·error·disabled·success 및 도메인 상태를 확인했다.
- [ ] 원본 이미지 권리·출처를 보존하고 미디어가 없을 때의 대안이 있다.
- [ ] 360px·200%·KO/EN·키보드·reduced motion에서 검수했다.
- [ ] Pretendard 실제 렌더링과 missing font 여부를 확인했다.
- [ ] Figma 구현 주석과 사용자에게 보이는 문구를 분리했다.
- [ ] 변경 후 실제 화면 스크린샷을 확인하고 검수한 범위와 미검수 범위를 기록했다.

현재 체크리스트는 이후 디자인 작업의 완료 조건이다. 이 문서 작성만으로 체크하지 않는다.

### 필수 검수 사례와 증거

| 대상 | 넣어 볼 실제 조건 | 통과 기준 |
| --- | --- | --- |
| Chip | `문화·예술·역사`, `Travel at a relaxed pace`, 선택+해제 | 전문 표시, 44px 영역, 줄바꿈 후 겹침 없음 |
| FeedPost | 2~3줄 제목 + 긴 장소명 + 출처 + 담기 | 본문과 행동 충돌 없음, 저장 두 의미 유지 |
| TripItem | 긴 장소명 + 시각 + 잠금 4종 + 편집 메뉴 | 제목이 밀려 사라지지 않음, 삭제·메뉴·잠금 각각 조작 가능 |
| PostPhotoField | 단일 사진 + 긴 실패 사유 + 다시 선택/재전송 | 사유 전문, 44px 행동, 캡션·해시태그·선택 장소 유지 |
| NavBar·TabBar | 긴 영어 label + 뒤로/보조 행동 + 확대 | 숨겨진 목적지 없음, focus와 읽기 순서 일치 |
| 달력 | 월 경계·선택 범위·비활성 날짜·200% 확대 | 모든 날짜와 선택 범위에 가로 스크롤 없이 접근 |
| Sheet·dialog | 긴 개인정보·출처 설명 + 키보드 표시 | 닫기·본문·최종 행동 접근, 배경 오작동 없음 |
| 데이터 카드 | 출처 전문·서로 다른 기준 시각·데이터 없음 | 출처 누락 없음, 가짜 개선 수치 없음 |
| 로그인·작성 | 실패 후 긴 입력값·이탈·재진입 | 계약에서 보장하는 입력 보존과 복구가 화면에 일치 |

대표 조합은 393px KO, 360px KO/EN, 200% 확대 KO/EN이다.
393px에서만 화면 밖 요소가 없다는 검사로 반응형 통과를 선언하지 않는다.
고정 좌표 Figma 스크린샷만으로 브라우저 확대·키보드·스크린리더 통과를 선언하지 않는다.

각 검수 기록에는 `기능 ID / component 또는 node / state / locale / viewport·zoom /
검수 방식 / 결과 / 증거 / 남은 이슈`를 남긴다. 아직 수행하지 않은 항목은 미검수로 둔다.

### 남은 확인 사항

- Pretendard를 Figma에서 실제 사용할 수 있는지와 한글·영문 실렌더링.
- 기존 컴포넌트가 이 문서의 신규 layout/state를 수용하는지와 영향받는 instance 목록.
- 현재 앱 shell에 넓은 화면 최대 폭과 좁은 달력 대안을 적용할 때의 시각 검수.
- 미확정 P1 필터·최근 검색·승계 계약, 업로드 크기·형식·TTL의 최종 값.
- 아직 승인되지 않은 사진·지도·경로 provider의 자산과 attribution.

이 항목들은 문서의 누락을 감추기 위한 기본값으로 채우지 않는다.
관련 화면에는 확인이 필요한 설계 주석을 남기고 확정된 기능의 리뉴얼은 계속 진행한다.

## 14. 문서 최종 평가

2026-09-20, 버전 1.3의 앱 디자인 명세 완성도는 **90/100점**으로 평가한다.
평가자는 작성·보완을 수행한 동일 에이전트이며 독립 전문가 검증이나 사용자 테스트 점수가 아니다.
Impeccable의 제품 맥락·정보 위계·상태·인지 부담 관점과 design-system-patterns의
토큰 계층·컴포넌트 재사용·변경 관리 관점을 문서에 적용한 정성 평가다.
Impeccable 엔진은 미설치로 실행되지 않았으며 자동 UI 검사·독립 이중 평가·실화면 검수는 미수행이다.

| 평가 항목 | 점수 | 근거와 남은 한계 |
| --- | --- | --- |
| 제품 정체성·기능 보존 | 19/20 | 후보·일정·게시물 의미, P0/P1 경계 명확; 최종 node별 대조 필요 |
| 시각 체계·토큰 | 18/20 | 색·서체·공간·계층·변경 규칙 연결; Figma 변수 매핑 미검수 |
| 컴포넌트 제작 명세 | 18/20 | 구성·상태·긴 문구·조합 명시; 실제 master 수용 여부 미확인 |
| 흐름·오류·접근성 | 19/20 | 입력 보존·복구·확대·키보드 기준 구체적; 실행 증거 필요 |

남은 점수는 규칙을 더 늘려 채우지 않는다. 피드·일정·chip 대표 화면을 이 규격으로 제작한
전후 이미지, 긴 KO/EN 문구와 확대 검수, 실제 토큰·instance 매핑 기록으로 보완한다.
새 평가 시 같은 항목과 배점을 유지하고 점수 변화의 증거를 적는다.
