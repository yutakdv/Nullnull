# NULLNULL P0~P1 리디자인 계획

작성: 2026-09-20. 기준: [DESIGN.md v1.4](DESIGN.md).
대상: [03 UI ReDesign](https://www.figma.com/design/C3tTNClo9JH8tb4qpQgP61/Nullnull-UI-Design?node-id=804-4475).
이번 산출물은 화면 관찰에 근거한 실행 계획이다. Figma와 코드 변경은 아직 수행하지 않았다.

## 1. 조사 범위와 근거

페이지 전체 메타데이터로 화면 구조·이름·위치·크기를 조사하고 아래 22개 프레임은
Figma에서 렌더링한 스크린샷을 직접 확인했다. 전체 상태의 시각 검수를 완료한 것은 아니다.
터치 영역, 실제 폰트, Auto Layout 설정, 브라우저 스크롤·접근성은 이미지로 확정하지 않는다.

검색 S12와 알림 S12가 충돌하므로 기존 ID는 보존하고 기능 ID·route·node로 구별한다.

### 게시 작성 최신 결정과 계약 게이트

- 2026-09-20 결정: 게시물은 운영자 검토 없이 성공 즉시 공개한다.
- 참고 범위: 소셜 앱의 사진 우선 작성 순서만 참고하고 NULLNULL의 색·표면·여행 장소 중심 구조를 유지한다.
- #312와 최신 제품 결정 반영: 제출 범위에 포함하며 익명 session 작성이 가능하다. 게시 사진 1장·캡션/인라인 해시태그·최대 50곳 연결 구조를 제공한다. 별도 제목 필드는 없다.
- 입력은 OS file picker 하나이며 capture·getUserMedia·다중 사진·별도 해시태그 필드는 제공하지 않는다.
- 권리 안내는 직접 촬영·제작 및 공개 동의 문구로 표시한다. 체크박스는 없다.
- createPostImageUpload → 파일 PUT → createPost 동기 완료 흐름이며 201에서 공개 완료를 알린다.
  post PENDING/PROCESSING·폴링·수동 검토 화면은 만들지 않는다.
- 크기·형식·TTL 및 제안 operation/schema의 최종 확정 여부는 구현 시 OpenAPI·생성 client와 대조한다.
  이번 디자인 수정은 계약 확정 또는 코드 구현 완료를 의미하지 않는다.
- Final 컴포넌트: PostPhotoField `946:657`, PostPhotoPreview `946:551`,
  PostCaptionField `946:684`, PlaceAttachment `946:766`, PostPublishBar `946:793`.
- 진입은 피드의 `게시물 작성` 행동에서 `/posts/new`를 여는 설계안으로 연결한다.
  컴포넌트 검토 후 전체 화면 조립에서 실제 진입 node와 상태별 화면 node를 확정한다.

## 5. 공통 컴포넌트 적용 방법

1. 기존 C번호·master·instance 연결을 조사하고 공유 master 변경의 영향 범위를 기록한다.
2. 리뉴얼 variant는 원본과 나란히 검수한다. 사용자 Trip header와 두 S07-4를 덮어쓰지 않는다.
3. FeedPost/C34, TripItem/C38, Chip/C48을 먼저 제작하고 NavBar/C49·Bottom CTA/C11을 연결한다.
4. 짧은 KO, 긴 EN, 아이콘 없음, 잠금 0~4개, 선택/해제, 오류 전문으로 크기 변화를 검증한다.
5. Search/C10·Sheet/C44·Toast/C35·Compare/C32·StateLabel에 같은 규칙을 전파한다.
6. 새 상태는 독립 속성으로 추가하고 모든 상태 조합을 거대 variant로 복제하지 않는다.
7. 검수된 component만 화면군에 전파하고 export/구현 단계에서 DESIGN.md의 토큰 이관 규칙을 따른다.

## 6. 완료 판정과 인계

- 디자인 범위의 모든 P0/P1 기능에 `원본 node / 새 node / state / component / 계약 근거 / 검수 결과`가 연결된다.
- 시각 확인하지 않은 프레임은 ‘미확인’, node가 없는 상태는 ‘설계 필요’로 남긴다. 존재만으로 완료 처리하지 않는다.
- 긴 제목·출처·chip 전문이 보이고 아이콘/행동과 충돌하지 않는다. 필요한 조작 영역은 최소 44px다.
- 화면의 제작 메모, 미확정 provider, 근거 없는 실시간/검증/성공 문구가 제거되거나 annotation으로 이동한다.
- 후보 담기·게시물 보관·일정 추가·미디어 업로드 진행·즉시 공개 완료를 구별하고 preview 승인 전 변경하지 않는다.
- 393px 기본, 360px KO/EN, 확대 대응 구조, 긴 오류·키보드·focus·reduced motion 검수 항목을 남긴다.
- Figma는 리플로우 설계와 시각 증거를 제공한다. 실제 200% 확대·키보드·스크린리더 통과는 구현 검증 뒤 기록한다.
- 최종 인계는 전후 캡처·변수/컴포넌트 매핑·상태 연결표·남은 계약 항목으로 구성한다.

현재 계획 확정에 필요한 화면군 관찰은 수행했으나 전체 instance 속성·모든 상태·실행 동작 검증은 D0 이후 작업이다.
완료된 디자인 계획과 아직 수행하지 않은 리디자인 제작을 구분한다.
